# TECHMAP-GRAPHER

Система проектирования жгутов и подготовки производственной документации.

## Текущее состояние

Основной опрос завершён; план M0–M9 и решения A01–A03 приняты владельцем.
Завершены M0-01 (обследование справочников), M0-02 (интерактивный эксперимент
текстуры вдоль направляющей) и M0-03 (поиск большого каталога и нагрузка Canvas).
Ожидаются формы документов. Полноценного приложения пока нет.
Рабочие решения находятся в [docs/requirements-notes.md](docs/requirements-notes.md),
макеты — в `design/mockups/`, предоставленные примеры — в `design/references/`.

Это рабочие материалы, не итоговое техническое задание. ТЗ и инструкция
составляются только по отдельной команде владельца проекта.

Оставшиеся вопросы, оценка объёма уточнений и правила продолжения работы:
[docs/collection-status.md](docs/collection-status.md).

Для продолжения работы:
- [Аудит требований и решения A01–A03](docs/requirements-audit.md).
- [Принятый план разработки M0–M9](docs/development-plan.md).
- [Текущее состояние и следующий шаг](docs/work-state.md).
- [Подтверждённые контрольные примеры](docs/acceptance-examples.md).

План утверждён, старт M0 разрешён. Работа выполняется ограниченными карточками.
M0-01: [владение данными и пробелы](docs/data-contracts.md),
[фактическая схема источника](docs/source-schema.md).
M0-02: [открыть локальный HTML-стенд](experiments/m0-02/index.html),
[результаты эксперимента](docs/m0-02-texture-experiment.md).
M0-03: [открыть стенд каталога и нагрузки](experiments/m0-03/index.html),
[результаты и ограничения](docs/m0-03-performance.md).
Выпуск ТЗ и инструкции требует отдельной команды владельца.

Первая версия: приложение для Windows с установщиком, локальными данными,
редактором схем и чертежей, библиотеками компонентов, маршрутами сборки,
картами резки/обжима и учётом выполнения. Дальнейшее размещение — сервер локальной сети.

Обновления установщика должны сохранять проекты и базы, предварительно создавать
резервную копию и переносить структуру данных при необходимости.

## Работа с репозиторием

Репозиторий является основным местом хранения проекта. Изменения фиксируются
осмысленными коммитами. Не включать пароли, ключи SSH, токены, локальные
пользовательские настройки и временные файлы. Производственные данные и внешние
базы не публиковать автоматически: используемые подключения и импорт отделены от кода.
