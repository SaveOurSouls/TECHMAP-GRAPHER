## Результат и границы

Оценить подтверждённый срез, архитектуру и оставшиеся риски. Устранить дублирование жизненного цикла JSON HTTP-запроса в четырёх API, сохранив URL/basePath, CSRF, revision/writer contracts, предметную валидацию, классы ошибок и отмену поиска справочника. Общий транспорт не зависит от editor/manufacturing и не выполняет автоматические повторы мутаций.

Массовая переработка геометрии, смена хранения и новая поставка ZIP не входят в безопасный объём этой карточки. Автоматические проверки не означают ручную приёмку.

## Критерии приёмки

- Отчёт различает подтверждённые результаты, исторические данные и ограничения; содержит ссылки на код и проверки.
- Четыре API используют общий транспорт; их публичные интерфейсы и политика ошибок сохранены.
- Регрессии проверяют отмену, сетевые ошибки, malformed JSON, HTTP-конфликты и ошибки валидации без повторной отправки.
- Полный клиентский набор, TypeScript/Vite, .NET functional/architecture и отдельный performance gate проходят.
- Результат закоммичен, опубликован, точный handoff и coverage заполнены; owner acceptance открыта.

## План проверки

Профильный baseline четырёх API; после реализации профильные и полный Vitest, TypeScript/Vite, .NET Release без performance-теста, затем performance отдельно; `git diff --check` и staged review. UI и portable не меняются, новая проверка пакета не заявляется.
