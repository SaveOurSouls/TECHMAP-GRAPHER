## Наблюдение и решение

На скриншоте прежние боковые списки занимают место около этапов; владелец заменяет такой доступ кнопкой у каждого этапа. Окно должно явно показывать выбранный этап, доступные ресурсы и результат добавления. Для этапов, которые не принимают входы по действующему контракту DAG, интерфейс должен объяснять ограничение или создавать допустимую сборку без скрытого изменения топологии. Отдельная карточка компонента объединённого полуфабриката не равна входу всей объединённой строки.

«К проекту» в текущем коде вызывает только `setEditorOpen(false)`, что закрывает редактор и оставляет карточку выбранного проекта. Ожидаемый переход — меню/список проектов. Проверка сохранения маршрута и проекта остаётся обязательной; отказ перехода не должен быть молчаливым.

## Критерии приёмки

- У каждого этапа видна «+ Добавить»; она открывает окно для конкретного этапа со списками сырья и полуфабрикатов. Боковые закреплённые списки не занимают основной экран маршрута.
- Добавление допустимого ресурса сохраняется в маршруте. Дубли, циклы, несохранённые и объединённые компоненты не проходят как невалидные входы; причина ограничения видна.
- Окно закрывается явной кнопкой и с клавиатуры; выбор и прокрутка доступны на узком окне.
- «К проекту» возвращает к меню проектов после успешной проверки сохранения. При конфликте/ошибке отображается причина, а данные не теряются.
- Навигация между «Схема Э4», «Чертёж» и «Маршрут», рисунки оболочек, связи и производственные длины остаются корректными.
