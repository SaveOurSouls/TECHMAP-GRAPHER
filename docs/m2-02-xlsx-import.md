# M2-02: безопасный импорт XLSX

Дата: 2026-09-12. Статус: реализовано.

## Результат

В разделе «Справочники» пользователь выбирает локальный `.xlsx`, указывает
идентификатор источника, лист, строки заголовков и данных, тип записи и ключевой
столбец. По умолчанию все остальные столбцы импортируются с исходными именами.
Ручное сопоставление позволяет задать имя поля, тип, обязательность, допустимость
пустой ячейки и список маркеров «не применимо».

Проверка создаёт на сервере временный candidate и показывает до 100 строк,
счётчики и адресные diagnostics. Активная версия справочника не меняется. Публикация
выполняется отдельной кнопкой, принимает только opaque `previewId`, хеш проверенного
candidate, точную active baseline и полный набор подтверждённых warning ID.

## Семантика данных

- отсутствующая ячейка не создаёт поле payload;
- физически пустая ячейка хранится как пустая строка, если разрешена;
- числовой `0`, текстовый `"0"` и логическое значение сохраняют исходный тип;
- ключ обязан быть непустым текстом, поэтому ведущие нули не теряются;
- настраиваемый маркер «не применимо» становится JSON `null` только при явном
  разрешении для поля;
- формула в строке импортируемого диапазона является блокирующей ошибкой, cached
  value не используется.

## Формат исходной таблицы

Универсальный импорт обрабатывает один лист за одну публикацию. В указанной строке
должны находиться текстовые заголовки, а каждая следующая строка представляет одну
запись. Один из столбцов выбирается ключевым: он должен содержать уникальный
непустой текстовый артикул или код. При автоматическом сопоставлении остальные
столбцы становятся характеристиками с исходными именами.

В portable-пакет включены `Examples/reference-catalog.xlsx` и краткая памятка с
готовыми настройками. Это синтетический справочник проводов, предназначенный только
для проверки механизма импорта.

Рабочая книга `База данных. Технология.xlsx` пока не является входом универсального
режима целиком. В её листах есть формулы, незавершённые строки, повторяющиеся ключи,
а `СПР.КАБ` содержит две таблицы на одном листе. Для неё нужны профильные правила
выбора таблиц и формирования ключей; они входят в последующие карточки M2.

## Защитные ограничения

Файл ограничен 25 МиБ. Проверяются ZIP-пути, количество и размеры частей,
индивидуальный и общий коэффициент сжатия, внешние relationship, content types,
макросы, ActiveX, OLE, embeddings и другие активные части. Чтение ограничивает
число листов, XML-строк, столбцов, ячеек, shared strings, diagnostics и размер
candidate. Одновременно выполняется одна проверка XLSX; в памяти хранится не более
восьми preview общим оценочным объёмом до 64 МиБ, сроком 30 минут. Перезапуск
приложения удаляет только временные preview, опубликованные версии остаются в SQLite.

Из внешних relationship разрешены только обычные абсолютные HTTP/HTTPS-гиперссылки.
Импортёр не открывает их и не сохраняет URL в снимок. Связи с внешними книгами,
локальными файлами, шаблонами, OLE-объектами и источниками данных блокируются.

Файл передаётся локальному loopback API как Base64 в JSON. Это временная форма
транспорта для portable Web-версии; браузер не возвращает materialized candidate
при публикации. Один `sourceId` закрепляется за типом адаптера. Для XLSX fingerprint
включает байты файла, безопасное имя файла и полное mapping, поэтому изменение
интерпретации создаёт самостоятельную версию.

## Проверка пользователем

1. Открыть «Справочники» и выбрать XLSX с текстовым ключом `RecordKey` в строке 1.
2. Оставить первый видимый лист, строки 1/2 и значения `generic-record` / `RecordKey`.
3. Нажать «Проверить файл» и убедиться, что активная версия ещё не изменилась.
4. Просмотреть таблицу и diagnostics, подтвердить каждое предупреждение и нажать
   «Опубликовать».
5. Изменить настройки или файл: прежний preview должен стать недействительным,
   а прежняя опубликованная версия сохраниться до новой успешной публикации.

Конкретные профили `БД.ОП`, `БД.ОБ`, `БД.ТЕР`, `БД.КОАКС`, `СПР.КАБ` входят в
M2-10. Быстрый поиск по опубликованным данным входит в M2-03/M2-04.
