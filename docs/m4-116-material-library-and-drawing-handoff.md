## Порядок сборки ZIP

1. Проверить `git status --short` и убедиться, что в собираемый HEAD входят
   только проверенные коммиты. Текущая версия в `package/VERSION.json` —
   `0.63.10-m5-07-review`; сравнить её с последним выданным ZIP.
2. Если версия совпадает с последним выданным архивом, увеличить `appVersion`
   в `package/VERSION.json`, создать и отправить отдельный коммит версии до
   запуска упаковки. Имя архива должно быть
   `TECHMAP-GRAPHER-<appVersion>-win-x64.zip`.
3. Собрать Windows x64:

```powershell
pwsh -File scripts/build-package.ps1 -Configuration Release -ArtifactSlice m4-116-20260930-materials
```

4. Для созданного каталога пакета повторно запустить `scripts/verify-package.ps1`.
   Затем выполнить `scripts/test-portable-package.ps1` для всех семи portable
   режимов. При проблеме ACL исходного пути повторить из ASCII-пути и записать
   это ограничение явно.
5. Зафиксировать в acceptance-протоколе исходный commit кода, версию, точный
   размер ZIP, SHA-256, число файлов манифеста, результаты семи portable-режимов
   и факт ручной UI-приёмки. ZIP оставить вне Git; в Git отправить только
   протокол и относящуюся документацию.

## Ограничения

Этот handoff не утверждает нормативное соответствие штриховок и не назначает
физические свойства материала по узору. Полный сценарий нанесения штриховки на
изогнутый пайп и ручная проверка пользовательского чертежа остаются частью
приёмки. В репозитории могут находиться изменения других карточек; их нельзя
подмешивать в этот ZIP без отдельного проверенного коммита.
