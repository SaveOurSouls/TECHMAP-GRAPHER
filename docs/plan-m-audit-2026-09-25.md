   пользовательских веток и оценка 15–18 проходов с повторными проверками.

(`01a0b219-4dea-73a2-bd09-df017671d332`) и прочитан непосредственно из сохранённого

## Вывод о стадии

Проект имеет работающий конструктор жгутов с развитой библиотекой, Э4, физическим
чертежом, кабелями, разделкой, покрытиями и связанными таблицами. Это стадия
развитой инженерной альфа-версии с проверенными отдельными поставками.
Текущая линия разработки — **M4**, последняя карточка — **M4-110**.

Сквозной производственный MVP из плана 18 сентября ещё не завершён: нет рабочего
графа операций/полуфабрикатов, связанного с ним расчёта времени и единой
производственной выгрузки. До полной V1 остаются существенные M5–M9 и остатки M2/M4.
Закрытие M4-105 относится к конкретному ТЗ физической топологии, а не ко всему
исходному M4 и тем более не к V1. M4-111 — следующий номер карточки, не оценка остатка.

## Сверка всех 27 карточек отдельного плана M

«Реализовано» означает наличие основной функции и относящихся к ней тестов/протоколов.
Это не заменяет все исторические условия пользовательской приёмки. «Частично»
означает конкретный незакрытый критерий; отсутствие доказательства явно отмечено.
Названия файлов ниже — проверенные ориентиры внутри `src`, если не указан `docs`.

| Карточка | Оценка | Реализовано и что осталось |

| M-01. Проверяемая исходная точка | Частично | Есть чистый зафиксированный baseline, VERSION.json и протокол M4-110. README описывает M4-12/14, Directory.Build.props хранит старую сборочную метку M3-05; единый актуальный реестр отстал. ProductVersion читает VERSION.json, поэтому это не доказательство неверной версии поставляемого UI. |
| M-02. Черновик библиотеки | Частично | ComponentLibrary сохраняет серверные drafts, публикует при open/new и автоматически сохраняет через 900 мс вне режима рисунка. Общая защита ухода/закрытия библиотеки не подтверждена: draft библиотеки не включён в App transition guard; автосохранение рисунка отключено. Нужен сценарий ухода до сохранения и при ошибке. |

Независимый от порта recovery и сохранение двух конфликтующих копий не закрыты. |

| M-08. Хранение и миграция Э4 | Реализовано | Parser, серверные validators v4/v5, библиотечное хранение, snapshots, migration/API/portability tests. |

производственные расчёты. Не считать их закрытыми только по общему заголовку M4.

## Предлагаемый порядок оставшейся работы

1. Закрыть достоверность: M-05A, сохранность M-02/03, пробелы M-04; затем единый
   реестр статусов и короткий приёмочный сценарий библиотеки → экземпляр → два вида.
2. Завершить производственные данные: identity корпуса/терминала, совместимость,
   происхождение припусков, сравнение обновляемых источников. Не требуется ещё один
   цикл общего украшения редактора.
3. Сводные резка и материалы проекта из одной ревизии; проверить несколько жгутов,
   разные количества, разницу длины 1 мм и отсутствие двойного расхода.
4. Малый производственный маршрут M-18/19, интеграция существующих EX-02/03 через
   M-20/21. Разработка простого маршрута не требует завершения всех сложных покрытий.
5. Демонстрационный XLSX M-23 и единая portable-приёмка M-24. Это завершит малый MVP.
6. Для полной V1: оставшийся M4, развитые полуфабрикаты M5, оборудование M6,
   согласованные формы M7, задания/факт/контроль M8, итоговая приёмка M9.

Историческую оценку 15–18 проходов нельзя переносить на сегодняшний остаток:
часть выполнена, часть критериев осталась, добавились новые требования. Сроки и
процент готовности этот аудит не выдумывает. Окончательные формы документов по
последнему найденному реестру остаются внешней вводной; это ограничивает финальную
вёрстку, но не разработку демонстрационного экспорта и маршрута.

## Проверки и границы доказательств

- Повторно выполнены 1280/1280 клиентских тестов (133 файла) и TypeScript.
- Production build клиента прошёл. Остались предупреждения о размере основного
  JS (~1,16 МБ), browser-external модулях heic-to и смешанном dynamic/static import.
- Штатный pnpm test сначала остановился до тестов: среда попыталась выполнить
  install и потребовала подтверждение переустановки node_modules. Зависимости не
  переустанавливались; Vitest/TypeScript/Vite запущены напрямую из установленного
  node_modules, успешно.
- Повторно выполнен `dotnet test Techmap-Grapher.slnx --configuration Release
  --no-restore -- --minimum-expected-tests 1`: 901/901 тест, без пропусков,
  5 мин 33 с. Проверены Domain, Architecture и Web.
- Исторический протокол M4-110 сообщает 901 серверный тест, API, браузер и семь
  portable-режимов PASS. Эти браузерные/portable-проверки в данном аудите не повторялись.
- Пользовательские проекты не открывались, не мигрировались и не удалялись.
  Выводы о пробелах получены чтением актуальных контрактов и вызывающего кода;
  непроверенный интерактивный сценарий не выдаётся за воспроизведённую потерю данных.
