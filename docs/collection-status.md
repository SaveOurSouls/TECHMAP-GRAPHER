## Условия завершения сбора

- Для первой версии нет существенных двусмысленностей, влияющих на расчёты и данные.
- Формулы подтверждены примерами с ожидаемыми результатами либо явно отложены.
- Получены формы документов либо согласована их отсрочка.
- Согласованы проверяемые сценарии приёмки и границы последующих версий.
- Владелец подтвердил завершение сбора. ТЗ и инструкция выпускаются только по его команде.

## Работа при ограниченном контексте

- Git и рабочие документы — источник состояния, не память переписки.
- Перед продолжением читать README, requirements-notes и этот реестр, проверять git status.
- Каждую новую договорённость записывать; явно отличать решение владельца от предложения.
- После согласованных уточнений делать небольшой тематический коммит.
- Не включать внешние производственные базы и секреты в репозиторий автоматически.
- Локальный коммит и отправка на remote различаются; не утверждать отправку без проверки.
- После сбора подготовить конкретный план этапов для подтверждения владельцем.
  Технологический стек и порядок реализации пока не выбраны.
- Будущую реализацию делить на ограниченные задачи: цель, входные требования,
  затрагиваемые модули, исключения, проверка результата, состояние и следующий шаг.
- Незавершённую задачу передавать с описанием фактического состояния и проверок.
- При существенной неопределённости представить варианты и влияние на план,
  запросить решение до зависимой реализации; обычные обратимые детали решать самостоятельно.

## Основа будущего процесса (предложение, не утверждённый план)

Инженерия требований → согласование границ → архитектура и проверка рисков →
небольшие проверяемые приращения → интеграционные проверки → приёмка → выпуск.
Для каждого требования впоследствии связать решение, реализацию и проверку.
Ориентиры: ISO/IEC/IEEE 29148 (требования), ISO/IEC/IEEE 12207 (жизненный цикл).
Не заявлять сертификацию или полное соответствие стандартам.

Источники:
- https://www.iso.org/standard/72089.html
- https://standards.ieee.org/ieee/12207/5672
