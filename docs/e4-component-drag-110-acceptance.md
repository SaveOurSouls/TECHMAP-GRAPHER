## Запрос и подтверждённая причина

Владелец сообщил о задержках при перемещении любого компонента. C1 показывает
семь таблиц соединителей, оконцовку, провода и витые пары; статичный скриншот
подтверждает масштаб сцены, но сам по себе не измеряет время. Исходный файл
проекта не приложен. Надписи внутри изображения не использовались как инструкции.

`HarnessDesignEditor` вызывал `applyEditorCommand(move-connector)` на каждом
кадре предпросмотра. Помимо локальной геометрии это запускает согласование
физической модели и производственных документов. Для оконцовки команда также
вызывает `rebuildConnectorE4Wires`, включая поиск маршрутов автоматических проводов.
Воспроизведена задержка около двух секунд на кадр для оконцовки. Обычный перенос
таблицы в том же синтетическом документе существенно дешевле; одинаковая задержка
для всех компонентов исходного проекта без его файла не утверждается.

## Изменение

- Предпросмотр Э4 строит временный документ непосредственно из сохранённого
  состояния: переносит компонент, прилегающие плечи проводов, общие Т-узлы и
  ветви экранов. Сохраняются режимы carry/Shift, ID, концы проводов и длины.
- Кадры по-прежнему объединяются через существующий `requestAnimationFrame`.
  Совпадающие направляющие выравнивания больше не вызывают лишнюю перерисовку.
- При отпускании действует прежняя полная команда с проверками, точной
  трассировкой, историей и сохранением. Escape отбрасывает только предпросмотр.
  Формат документа, сервер и поведение Чертежа не менялись.

## Измерение до/после

Воспроизводимый запуск из корня: `node scripts/benchmark-e4-component-drag.mjs`.
Node v24.21.0; одна машина, последовательное сравнение методов на одном документе.
Синтетический документ проходит `parseHarnessDesignDocument`: 7 таблиц (до 13
контактов), оконцовка НВИ, 12 проводов по 500 мм, две витые пары. На каждом шаге
исходный документ один и тот же, меняется только координата. Один прогревочный
шаг и 8 измерений на метод/компонент/режим. Baseline — прежняя полная команда,
новый метод — фактически подключённый `previewE4ConnectorMove`.

  оконцовки с Shift, Escape, сохранение, Undo и Redo. Движение видно в canvas;
  до pointer-up сохранённые координаты не меняются. После него новые положения

В изолированном worktree использованы уже установленные зависимости через

## Ограничения и передача

Полная команда при отпускании остаётся синхронной: для оконцовки на тестовой
сцене её время около 1,9–2,1 с. Устранено повторение этой операции во время
движения; окончательная маршрутизация не ускорялась и не ослаблялась.
Во время предпросмотра линии могут временно пересекать препятствия; окончательная
проверка остаётся в прежней команде. Пользовательский проект C1, серверные тесты
и portable-пакет в этой карточке не проверялись. Серверный код не менялся.

ZIP не заказан и не собирался. Срез предназначен для следующего пакета после
M5-22-049; наличие опубликованной ветки не доказывает интеграцию. Сборщику нужны
code SHA выше и документационный SHA из [handoff](coordination/handoff-110-e4-performance.md),
затем ancestry/coverage в его HEAD. Приёмка владельцем открыта.
