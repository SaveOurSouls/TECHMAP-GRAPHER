# M2-06–M2-08 — граница формата графического шаблона v2

Дата решения: 2026-09-14. Статус: рабочий контракт для реализации.

## Назначение

Версия 1 уже сохраняет виды, четыре простых примитива и точки подключения. Версия
2 расширяет этот формат без смешения справочной записи, графического шаблона и
экземпляра в проекте. Миграция v1→v2 выполняется детерминированно при открытии:
создаются недостающие слои и значения свойств, координаты и ID существующих
объектов сохраняются.

## Идентичность и ссылки

- `templateId + version` однозначно определяет неизменяемую версию шаблона.
- Каждый вид, слой, примитив, логический контакт, точка и параметр имеет устойчивый
  UUID внутри шаблона. Подпись и номер можно менять без смены ID.
- Точка вида ссылается на `logicalContactId`. Один логический контакт может иметь
  по одной точке в нескольких видах; некоторые виды могут не иметь такой точки.
- Вспомогательный общий выход пучка является отдельным `bundlePort`, а не контактом,
  и не создаёт электрическую цепь.
- Экземпляр проекта позже хранит точные `templateId`, `templateVersion`, параметры
  и локальные переопределения. Обновление экземпляра до другой версии выполняется
  отдельной командой с диагностикой удалённых ID.

## Состав версии

Корневой объект содержит `schemaVersion`, `views`, `logicalContacts`, `parameters`,
`repeaters` и `assets`. Вид содержит упорядоченные слои; слой — упорядоченные
примитивы и группы. Видимость и блокировка принадлежат слою и объекту. Порядок в
массивах является порядком отрисовки и входит в каноническую версию.

Группа хранит только ссылки на дочерние ID и собственное преобразование. Физические
примитивы не копируются внутрь группы, поэтому группировка и разгруппировка не
меняют их идентичность. Циклы, повторное владение и отсутствующие ссылки запрещены.

Общие свойства примитива: `id`, `kind`, `layerId`, `visible`, `locked`, `opacity`,
`transform`, `stroke`, `fill`. Геометрия хранится в координатах вида. Поддерживаются:

- линия и ломаная из упорядоченных точек;
- прямоугольник с независимым или общим радиусом углов;
- круг/эллипс;
- свободная кривая Безье;
- замкнутый контур;
- текст;
- изображение по ссылке на asset.

Привязка угла с шагом 15° является настройкой жеста редактора. Сохранённый документ
содержит итоговые точки и не зависит от настройки рабочей станции. Визуальный
радиус изгиба также хранится в геометрии, но не считается физической длиной жгута.

## Параметры и повторение

Параметр имеет устойчивый ID, имя, тип, единицу, значение по умолчанию и допустимый
диапазон. Геометрическое свойство может быть константой или ограниченным выражением
над параметрами. Выражения не исполняют JavaScript и проходят отдельный парсер.

Repeater ссылается на одну группу-прототип, целочисленный параметр количества,
вектор шага и правила получения логических контактов/точек. Развёртывание всегда
детерминировано из `prototypeId + index`; результат не записывается как сотни
независимых фигур. Ноль, отрицательное количество, выход за лимит, повторяющиеся
номера и коллизии ID отклоняются до сохранения.

## Изображения

Asset хранит метаданные и SHA-256 содержимого; бинарный файл лежит в общем CAS.
Допустимы только явно разрешённые растровые форматы, размер и фактический MIME
проверяются по сигнатуре. Примитив изображения содержит `assetId`, рамку обрезки,
поворот, масштаб, прозрачность и флаг подложки.

Ссылка версии шаблона на asset неизменяема и входит в хеш версии. Backup содержит
все asset blobs глобальной библиотеки. Экспорт одного проекта не включает всю
глобальную библиотеку; когда экземпляры шаблонов появятся в проекте, проектный
экспорт должен включать только закреплённые версии и достижимые от них assets.

## Ограничения и диагностика

Сервер проверяет точный набор полей, конечные числа и пределы координат, уникальность
ID, ссылки на существующие слои/контакты/assets, ацикличность групп и выражений,
лимиты объектов/точек/assets и обязательные виды Э4/чертежа. Отсутствующий blob,
неподдерживаемый формат и удалённая точка, на которую ссылается экземпляр, дают
адресную диагностику и не заменяются пустым объектом.

## Порядок реализации

1. Расширить клиентские примитивы, слои и группы с чистым upgrade v1→v2.
2. Добавить schema хранения asset-ссылок, upload/read API и проверку backup.
3. Опубликовать серверную строгую схему v2 и сохранить новую версию шаблона.
4. Реализовать параметры и repeaters на одном эталоне 2/10 контактов.
5. Связать точки разных видов через `logicalContactId` и проверить диагностику
   удалённых связей.
