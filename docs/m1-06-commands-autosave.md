# M1-06 — ревизии, команды и автосохранение

Дата: 2026-09-12. Статус: завершено. Это отчёт карточки, не итоговое ТЗ и не инструкция.

## Реализовано

- SQLite schema 4 добавляет `projects.revision`, immutable `project_commands` и
  `project_versions`. Старые проекты при миграции получают исходную ревизию 0;
  новые и копии тоже начинаются с 0. Копия не наследует журнал оригинала.
- PATCH проекта, добавление/удаление жгута и добавление вложения требуют UUID
  `commandId` и `expectedRevision`. Принятая команда меняет предметные данные,
  повышает ревизию ровно на 1 и сохраняет результат в одной транзакции SQLite.
  Закрепление характеристики через командный store следует тому же правилу.
- Повтор того же ID с тем же каноническим содержимым возвращает исходный результат
  даже после последующих правок. Повтор ID с другими данными даёт
  `command_id_reused`; новый ID с устаревшей ревизией даёт `revision_conflict`,
  `currentRevision` и не создаёт запись журнала. Журнал хранит хэши запроса и
  ответа и историю принятия. GET проекта и списка возвращает ревизию; отдельный
  защищённый GET возвращает версии по порядку.
- Браузер объединяет частые правки карточки проекта за 1,5 с, отправляет по одной
  команде за раз и показывает pending/acknowledged/conflict/error. Подтверждение
  появляется только после ответа сервера. Маркер неподтверждённого черновика
  сообщает после перезапуска о возможной потере; навигация предупреждает.
- Вложения публикуются в content-addressed store до транзакции. Если команда
  отклонена, видимой ссылки не возникает; неподключённый blob безопасно остаётся
  для будущей уборки. Параллельные запросы сериализует writer gate SQLite.

## Границы

Создание и копирование проекта пока вне командного envelope, но результат
создаётся транзакционно с revision 0. Автоматический откат редактора Ctrl+Z входит
в M3. Исторический журнал хранит подтверждённые результаты, а не полную копию
проекта на каждой ревизии. Справочники и предметные редакторы пока отсутствуют.

## Проверка

Сценарий `scripts/test-m1-06.ps1`: locked offline restore, frontend typecheck/tests/
build, .NET Release build/tests, M0 regression, self-contained Windows x64 ZIP,
manifest и семь portable-режимов с перезапуском проекта и вложения.

Интеграционные проверки отдельно охватывают duplicate/replay после новой версии,
stale revision, изменённый payload, конкурентную запись, принудительный сбой
перед фиксацией версии, restart, HTTP-сессию и сохранённый снимок характеристики.
Итог: frontend 35/35, .NET 191/191, регрессия M0 20/20, Release build без
предупреждений; ZIP 45,56 МиБ (106,96 МиБ распаковано), семь portable-режимов.
Независимый review выявил и помог исправить replay изменившегося источника,
навигационную гонку UI, Unicode NFC, границу `Int64` и обязательность ревизии.
