# M0-05: архитектура, стек и инженерные бюджеты

Статус: завершено 2026-09-12. Зависимости: M0-01–M0-04R. Это архитектурное
решение для начала M1, не итоговое ТЗ и не готовое приложение.

## Решение

TECHMAP-GRAPHER строится как web-first модульный монолит. Обычный браузерный
клиент обращается только к версионированному JSON API. В локальной V1 сервер и
клиент поставляются одним self-contained Windows x64 ZIP; сервер слушает loopback
и открывает системный браузер. Будущий LAN-вариант сохраняет совместимость основного
клиента и публичного API, расширяя их авторизацией и совместной работой. LAN, роли
и совместное редактирование в V1 не реализуются.

Модули разделяются следующим образом:

- `Domain` — идентичность, единицы, электрическая/физическая модель и чистые расчёты;
- `Application` — команды, проверки, ревизии и права изменения модели;
- `Infrastructure.Sqlite` — транзакции, миграции, вложения, backup и архивы;
- `Web` — `/api/v1`, локальный запуск и статические файлы клиента;
- `Client` — React-панели, дерево, формы и собственный Canvas 2D renderer;
- адаптеры источников и экспорта зависят от Application, но не становятся частью Domain.

Схема, чертёж и маршрут используют одну предметную модель и разные представления.
DTO API не являются таблицами EF Core. Canvas-сцена хранится как версионированные
обычные данные и отделена от React DOM, hit-test и renderer. Это позволяет менять
отрисовку и строить PDF/PNG без переноса бизнес-правил в графическую библиотеку.

## Web-контракт

- Все команды и чтение продукта находятся под `/api/v1`.
- Клиент получает базовый путь приложения и API из runtime-конфигурации. Ресурсы и
  API нельзя навсегда привязывать к корню `/`: M1-01 проверяет размещение под префиксом.
- Неизвестный `/api/...` возвращает JSON 404 и не попадает в SPA fallback.
- Локально разрешены только loopback Host/Origin. До первой изменяющей команды в
  M1-02 реализуются сеансовый токен и защита от межсайтового запроса. CORS сам по
  себе этого не заменяет.
- Диагностические пути программы и данных доступны только в локальном режиме.
  В LAN они не публикуются.
- В клиенте нет прямого SQL, доступа к произвольным файлам и desktop API.
- Все JS/CSS/шрифты поставляются внутри ZIP; CDN и обязательный интернет запрещены.

SQLite открывает только сервер. Для одного `dataRoot` работает один процесс; второй
запуск находит защищённую запись активной сессии и открывает существующий экземпляр,
а при невозможности безопасного подключения выдаёт ошибку до открытия БД.
SQLite-файл нельзя размещать как общую базу на сетевом диске. Репозиторий/адаптер
хранения сохраняет возможность перейти на серверную СУБД в LAN без смены Domain/API.

## Кандидатный стек для locked restore

Точные кандидатные версии выбраны 2026-09-12 по официальным метаданным .NET,
NuGet и npm. Фактический restore, полный транзитивный состав и лицензии фиксируются
в M1-01 через `global.json`, NuGet lock в locked mode, `packageManager` и
`pnpm-lock.yaml`; диапазоны `^` и `~` для product build не применяются. Если хотя
бы один кандидат не восстанавливается из официального источника, M1-01 обновляет
решение отдельным документированным коммитом, не подменяя версию молча.

ClosedXML 0.105.1 для XLSX и PDFsharp/MigraDoc 6.2.4 для PDF остаются кандидатами
M7, а Canvas `toBlob()` — кандидатом для PNG. Они не добавляются в зависимости
M1. Точные package ID, transitive dependencies, лицензии и работа кириллических
шрифтов проверяются перед первой карточкой экспорта.

Стенд M0-04R на .NET 8.0.14 остаётся воспроизводимым доказательством упаковки,
но product solution начинается на .NET 10: поддержка .NET 8 заканчивается
2026-11-10, .NET 10 LTS — 2028-11-14. Официальные метаданные подтвердили
SDK 10.0.401 и Runtime 10.0.12; установка SDK 10 и первый полный locked restore
остальных кандидатов входят в M1-01.

Для таблиц не выбираются EPPlus без отдельного решения о лицензии. Для PDF не
выбираются iText (AGPL/commercial) и QuestPDF без проверки права на Community.
Electron, WebView2, Tauri, installer, микросервисы, Docker, PostgreSQL, SignalR,
PWA, WebGL/Pixi и полнотекстовый движок сейчас не входят в стек.

В каждом выпуске создаются `THIRD-PARTY-NOTICES`, locked inventory и SBOM. Шрифты
для PDF с кириллицей поставляются с проверенной лицензией, без зависимости от
набора шрифтов конкретного компьютера. Обновление любой закреплённой зависимости —
отдельный коммит с тестами, обновлением notices и проверкой размера ZIP.

## Предварительные инженерные бюджеты

Это цели M1–M4, а не уже достигнутые SLA. Они измеряются на согласованном
контрольном Windows-компьютере и окончательно подтверждаются в M9.

| Область | Фикстура | Предварительный критерий |
|---|---|---|
| Запуск | Release self-contained, 10 запусков | процесс → health p95 ≤ 3 с, max ≤ 5 с; интерактивная оболочка p95 ≤ 5 с |
| API | прогретый loopback, 30 повторов | health p95 ≤ 50 мс; обычное чтение p95 ≤ 100 мс; durable command p95 ≤ 500 мс |
| Проект M1 | 2 жгута, 10 МиБ модели | открыть и проверить p95 ≤ 1 с; UI интерактивен ≤ 1,5 с |
| Проект M3 | список 100 жгутов, выбранный жгут 300 простых проводов | список p95 ≤ 1,5 с; выбранный холст ≤ 2 с; 100 холстов сразу не загружаются |
| Проект M4 | 300 проводов с изгибами, слоями, текстурами и подписями | выбранный холст p95 ≤ 3 с |
| Сохранение | структурированные данные до 10 МиБ | атомарное сохранение p95 ≤ 1 с, max ≤ 2 с; подтверждение только после durable commit |
| Каталог M2 | 50 000 записей | ввод → видимый результат p95 ≤ 100 мс, max ≤ 200 мс; DOM ≤ 40 строк |
| Canvas M3 | 300 простых проводов, жест 5 с | input-to-paint p95 ≤ 33 мс, выбор ≤ 100 мс, ≥ 95% кадров в бюджете |
| Canvas M4 | 300 оформленных проводов, 30 повторов действия | input-to-paint p95 ≤ 50 мс, max обычного действия ≤ 200 мс; texture cache и dirty layers обязательны |
| Поставка | программа без пользовательских данных | M1 ZIP ≤ 75 МиБ/распаковано ≤ 200 МиБ; M4 ≤ 100/250 МиБ; пересмотр при ZIP > 150 МиБ |
| Память | каталог 50k + один холст 300 проводов | server private bytes: idle ≤ 150 МиБ, с проектом ≤ 300 МиБ; browser JS heap ≤ 250 МиБ |
| Backup | проект 10 МиБ, 10 запусков | backup p95 ≤ 3 с; проверенное восстановление в отдельный root p95 ≤ 5 с |
| Архив проекта | 100 МиБ, не менее 100 файлов, 10 запусков | экспорт max ≤ 20 с; импорт с полной проверкой max ≤ 30 с на SSD |

Методика: Release/offline; текущие стабильные Edge и Chrome, обязателен Edge
текущей Windows; пять прогревов и 30 измерений быстрых операций;
отдельно p50/p95/max. UI измеряется от действия до корректного кадра, а не только
время функции. Отчёт хранит commit, ОС, браузер, CPU/RAM, версии и размер фикстуры.

Фактический baseline M0: каталог 50 000 создан за 28,9 мс, поиск без DOM имел
p95 ≤ 2,7 мс, Canvas 300 прямых проводов — p95 11,3 мс с кешем и 126,5 мс с
перестроением текстур. M0-04R от commit `36861bd`: ZIP 41 519 975 байт
(39,60 МиБ), распакованный пакет 95 880 182 байта (91,44 МиБ).
Эти числа не доказывают полную скорость будущего редактора.

Для каждой карточки обязательны отсутствие необработанных исключений, минимум один
значимый ошибочный тест, одинаковый доменный результат в Edge/Chrome и фиксация
сырого отчёта. Порог меняется только отдельным решением с фактическими измерениями.

## Итог M0

Все пять карточек M0 завершены. Архитектурные риски имеют выбранные решения,
а остающиеся ограничения превращены в проверяемые карточки. Следующая работа —
M1-01 из `docs/m1-cards.md`; она создаёт product solution на закреплённом стеке,
не пытаясь сразу реализовать редактор или всю систему.
