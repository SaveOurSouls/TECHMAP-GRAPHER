# M0-01: владельцы данных и контракты источников

Дата: 2026-09-11. Рабочий результат архитектурной проверки, не итоговое ТЗ.
План M0–M9 и решения A01–A03 приняты владельцем: «Принимаем, стартуем».
В этой карточке проверена структура источника; промышленный импорт не реализован.

## Границы и результат

Цель: определить, какие данные приходят из базы, какие создаются в утилите,
и какие проблемы нужно устранить до подключения реальных справочников в M2.
Входит: чтение копии, заголовки, кандидаты ключей, заполненность, связи,
единицы, правила снимков и перечень пробелов. Не входит: изменение Google Sheets,
очистка записей, выбор стека, разработка приложения и расширение требований.

Результат: таблица владения ниже, [схема источника](source-schema.md),
реестр G01–G09 и условия проверки будущего адаптера. Карточка завершена как
обследование с выявленными пробелами, а не как приёмка пригодности базы к импорту.

Чтение выполнено с формулами и с сохранёнными результатами формул.

Сохранённые результаты пригодны для обследования, не для молчаливой подмены
согласованных расчётов приложения.

## Владение данными

| Данные | Владелец | Связь и граница |
|---|---|---|
| Артикул, производитель, физические характеристики | Внешняя база | Утилита хранит закреплённую копию и происхождение, справочник не переопределяет |
| Состав и номера контактов соединителя, группы типов, способы подключения | Внешняя база | Связь контакта с графической точкой хранится в шаблоне |
| Совместимые терминалы группы, диапазоны встроенных контактов | Внешняя база | Координаты, выбранный терминал и фактическое подключение относятся к экземпляру |
| Терминалы, диапазоны сечения/изоляции, длина зачистки | БД.ТЕР | Обжимной терминал даёт норму, чертёж содержит назначение конкретному концу |
| Послойная разделка для пары кабель–соединитель | БД.КОАКС | Нормы и диаметры приходят из источника, внешний вид из шаблона |
| Марка, сечение, диаметр изоляции, состав многожильного кабеля | Внешняя база проводов | СПР.КАБ содержит только часть данных о диаметрах, не заменяет полный каталог |
| Гофра, оплётки, трубки, стяжки, допустимые диаметры и расширение | Внешняя база аксессуаров | Шаблон хранит текстуру и визуальные параметры |
| Код операции, нормативные параметры, тип машины | БД.ОП | Повторы q, длина L и назначение в блок задаются в проекте |
| Артикул оборудования и физический инвентарный номер | БД.ОБ | Очередь, назначение рабочего места и резерв интервала создаёт проект |
| Рисунки, примитивы, виды, точки/направления, слои, текстуры | Библиотека утилиты | Привязка к версии справочной записи, без конкурирующих физических норм |
| Шаблон полуфабриката, разрешённые параметры, его маршрут | Библиотека утилиты | Материалы ссылаются на внешние справочники; экземпляр закрепляет версию |
| Проект, жгут, Э4, подключения, длины, припуски, маркировки | Проект утилиты | Идентификаторы экземпляров не равны артикулам |
| Блоки, зависимости, состояния этапов, технологические поправки | Проект утилиты | Поправки хранятся отдельно от исходного размера/нормы |
| Задания, выпуск, потребление, остатки, контроль | Учёт утилиты | Факты с историей корректировок; Ctrl+Z чертежа их не удаляет |
| XLSX, PDF, PNG | Производные документы | Ссылаются на версии проекта и справочников, не источник обратного редактирования |

Названия владельцев — логическое разделение. Они не требуют отдельных серверов
или баз данных для каждого модуля.

## Минимальный контракт адаптера

Ниже инженерное предложение формата для реализации M2; имена полей могут быть
уточнены при выборе хранения в M0-04/05 без изменения пользовательского поведения.

Каждая запись содержит `sourceId`, `entityType`, `sourceKey`, `snapshotId`,
`sourceLocation` (лист и адрес для диагностики), `payload` и `diagnostics`.
У снимка есть версия контракта, время получения, контрольная сумма и состояние
проверки. Адрес строки служит диагностике, но не устойчивой идентичности.
Внутренний ID экземпляра и ID шаблона независимы от внешнего ключа.

Адаптер преобразует источник в канонические сущности: операция, тип оборудования,
экземпляр оборудования, терминал, соединитель, группа контактов, контакт,
провод/кабель, профиль разделки, аксессуар, физический справочный тип.
Один артикул оборудования может иметь несколько инвентарных экземпляров.
Одинаковый артикул материала не объединяет разные графические экземпляры.

Google и XLSX дают одинаковый контракт. Доступ только на чтение. Импорт сначала
проверяется в отдельном снимке; ошибочная загрузка не заменяет рабочую базу пустой
или частичной. Диагностика привязана к записи/полю. Незавершённые справочные
записи не получают вымышленных значений и статуса «совместимо».
Точное поведение публикации неполного снимка уточняется при реализации M2,
с сохранением согласованных предупреждений и принудительного выбора.

Обновление справочника не меняет закреплённую версию проекта. Явное обновление
показывает изменения и не переписывает выданное задание или производственный факт.
Переносимый проект содержит используемые снимки, графику и версии связей.
Недоступный исходный сервис не мешает открыть сохранённый проект.

## Единицы и отсутствие данных

| Поле | Представление/правило |
|---|---|
| Длина и диаметр | Число в мм, отдельно от условных координат рисунка |
| Погонное время V | Сек/м; для L в мм вклад равен L / 1000 × V |
| W, S/T/U/Y, подготовка | Секунды по согласованному смыслу; единицу W требуется явно закрепить в контракте |
| q и K | Разные безразмерные количества: q повторяет операцию, K — действие инструмента внутри неё |
| Штучные материалы | Штуки; погонные материалы — метры, без округления промежуточных расчётов |
| AWG и мм² | Хранить исходную систему и границы; обратный порядок номеров AWG не считать ошибкой физического диапазона |
| L1…Ln | 0, пусто, «-» означают отсутствие слоя; нумерация от центральной жилы наружу |
| Время | 0 — известное отсутствие затрат; пусто — нет значения, не превращать в 0 |
| Технологическая поправка | Знаковое число, отдельно для каждого конца, не замена норматива базы |
| Артикул/инвентарный номер | Текст с сохранением ведущих нулей и значимых символов |

Текстовые десятичные значения с запятой можно разбирать по согласованной локали.
Диапазоны в одной строке не превращать в одно число. Не извлекать артикул
универсальным разделением по «/»: символ может входить в сам артикул.
Единицу расхода на настройку нужно хранить отдельно от величины.
Исчезнувший столбец — ошибка схемы, пустая ячейка — состояние значения.

## Реестр пробелов

| ID | Подтверждённое наблюдение | Что требуется и когда |
|---|---|---|
| G01 | 126 кодов операций уникальны в текущей выборке. Другие кандидаты ключей имеют повторы | До M2 определить устойчивые ключи, при необходимости добавить ID в источник. Не склеивать строки по первому совпадению |
| G02 | 67 непустых полей «Машина»: 0 точных совпадений с артикулом БД.ОБ!D; 58 совпадений с «Для базы» БД.ОБ!L среди строк с артикулом | Нужен явный переход от подписи к типу оборудования, проверка оставшихся 9 ссылок и неоднозначностей. Совпадение подписи ещё не подтверждает связь |
| G03 | Из 146 строк оборудования с артикулом у 8 не заполнен инвентарный номер | До M6 заполнить/классифицировать экземпляры. Не создавать фиктивные станки из пустых номеров. Повтор артикула сам по себе нормален |
| G04 | В БД.ОП есть все S–Y, но Y пуст у всех 126 операций; R содержит «Погонный», «Переменный», «Статичный» | До расчёта реальных норм уточнить отсутствие значений и драйвер переменного типа. Не считать пустое Y нулём и не угадывать формулу типа по названию |
| G05 | Терминал: производитель + REEL + BAG даёт 40 повторяющихся групп. Коакс: артикул + провод даёт 4. СПР.КАБ: название даёт 1 | Разделить истинные дубли и варианты технических требований. Согласовать ключ профиля/варианта и связь упаковок. Числа относятся к кандидатам, не к доказанным ошибочным дублям |
| G06 | В проверенной книге нет отдельных БД.ПРОВОД, базы соединителей и базы аксессуаров; СПР.КАБ имеет только кабель и D1–D3 | Получить расположение/схемы остальных источников до M2. Нужны сечение и изоляция проводов, контактные группы, совместимость, способы подключения, аксессуары |
| G07 | В БД.КОАКС ровно D1–D3 и L1–L3; в требованиях число слоёв переменное | В контракте массив слоёв с номером. До подключения расширенных случаев согласовать дополнительные столбцы либо отдельную таблицу слоёв |
| G08 | Нормы и ограничения заполнены не у всех строк: например длина зачистки у 223 из 279 кандидатов терминалов | До M2 различать незавершённые записи, неприменимость и заданный ноль. Недостающий предел не означает неограниченную совместимость |
| G09 | Расход на настройку имеет общий заголовок «м; шт;», нет отдельного столбца единицы. Связи на инструменты/модули операций пока пусты в проверенной выборке | До M6 закрепить единицу и нужный состав оборудования для полного рабочего места. Не выводить комплект из свободного названия операции |

G01/G05 касаются идентификации справочников, а не согласованного объединения
полностью идентичных строк производственного задания. Эти правила не взаимозаменяемы.
Пробелы не мешают M0-02/03 на синтетических данных. Исправление источника в эту
карточку не входит; вопросы владельцу сгруппировать к подготовке M2.

## Проверки и ограничения

Выполнены: чтение заголовков пяти таблиц, подсчёт заполненности, кандидатов ключей,
сопоставление подписей машин, поиск сохранённых ошибок формул и сверка единиц.
Метод выборки и полные заголовки — в source-schema.md. Файлы источника,
производственные строки и сырой текст формул в Git не включены.
Не выполнены: пересчёт исходной книги, проверка достоверности физических норм,
полный аудит всех 15 листов, импорт, программные тесты приложения.

Будущий адаптер должен демонстрировать: (1) перестановка строки сохраняет связь
по ID, (2) одинаковый ключ с разным содержимым даёт диагностику, (3) пустое время
не становится нулём, (4) 20 мм правильно переводятся в 0,02 м, (5) пропавший
источник оставляет прежний снимок, (6) обновление не меняет выданные задания.
Это критерии последующей проверки, а не уже пройденные тесты.

Следующая ограниченная карточка: M0-02, эксперимент направляющей и повторяемой
текстуры с ручным размещением и отключением привязки.
