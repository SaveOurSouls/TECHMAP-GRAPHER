## Аудит и план этапа

1. Проверить скриншот: в колонке «Терминал» показывался составной ключ БД.ТЕР.
2. Проверить источник названия контакта: для размещённого шаблона authoritative source — `libraryBinding.snapshot.contacts`, сопоставление по `logicalContactId`.
3. Сохранить полный composite key для выбора и команд, но декодировать второй сегмент для подписи.
4. Отобразить название в графическом Э4-блоке, HTML-предпросмотре библиотеки и Canvas renderer.
5. Добавить регрессии, пересобрать клиент/сервер, проверить изолированное API-размещение и собрать ZIP без пользовательских данных.

## Реализация

- Для отображения терминала используется `terminalArticleLabel`. Ключ вида `3:JST|14:SPH-002T-P0.5S|0:|3:PHR` показывается как `SPH-002T-P0.5S`; исходный ключ сохраняется в `ConnectorContact.terminalArticle`, option value и snapshot.
- Название контакта в библиотечном предпросмотре берётся из строки серии и передаётся через `templateAuthoring`; тип группы не используется как подмена названия.
- Metadata Э4 передаёт короткий terminal label в Canvas renderer. Старые документы без имени читаются с пустой подписью.
- Справочные пояснения остаются в `InfoHint`; пользовательские проекты не открывались и не удалялись.
