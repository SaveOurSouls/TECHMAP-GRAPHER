## Аудит и план этапа

1. Подтвердить исходную сборку и путь команды изменения цвета/перемещения.
2. Убрать связь размера цветовой ячейки с трассировкой и откат перемещения
   при временной геометрической коллизии; отдельно показывать диагностику.
3. Сравнивать допустимые наборы трасс, а не брать первый успешный порядок.
4. Для экранного отвода на провод проецировать узел на прямой участок цели;
   пересчитывать его при перемещении экрана. Запретить обходы такого отвода.
5. Регрессии, сборка, проверка API на синтетическом проекте, ZIP без данных.

Исходные 726 клиентских тестов прошли. Обнаруженная причина цвета:
`connectorE4TableGeometry` учитывала длинное название цвета, хотя ячейка рисуется
образцом. Рост ширины менял контактные точки, запускал `rebuildConnectorE4Wires`,
и исключение отменяло изменение цвета. `move-connector` также отменял команду
при неудаче маршрутизатора. Пакетный поиск пробовал несколько порядков, но
возвращал первый результат. Экранный отвод использовал обычную трассировку,
допускавшую изгибы.

## Правила трассировки и принятые решения

Это аудит внутренних правил и обычных приёмов оформления электрических схем,
не сертификация соответствия стандарту.

| Правило | Результат проверки |
| --- | --- |
| Электрическая связность отдельно от рисунка | Пересечение не соединяет цепи; явный junction сохраняет соединение. Цвет не должен менять геометрию. |
| Ортогональные участки, вывод из контакта наружу | Сохраняются: провод не выходит в тело таблицы, минимальный обычный вывод 24. |
| Пересечение двух прямых | Допускается, автоматический поиск штрафует его; касания без узла, наложения и самопересечения запрещены. |
| Читаемый зазор | 21 — внутренний размер места под перемычку с ореолом, не физический размер провода и не число из стандарта. Сохраняется и при отключённой отрисовке мостика. |
| Обход таблиц и подписей | Сохраняется зазор 4 от таблицы; подпись собственной электрической сети не блокирует вход её ветви в узел. |
| Качество всего набора | Сравниваются сумма длин, 8 за изгиб и 84 за пересечение без электрического узла. Выбирается лучший проверенный набор. |
| Работа оператора при конфликте | Перемещение обычного блока сохраняется. При необходимости восстанавливаются ортогональные концы с прежней связностью; конфликт с препятствиями остаётся диагностикой. Следующий drag снова ищет маршруты. |
| Экран → узел на проводе | Ровно один прямой участок наружу от вывода. Узел проецируется на ближайший доступный перпендикулярный участок того же провода, все участники узла проверяются. Короткий отвод допустим: вывод 24 здесь не применяется. |
| Экран → контакт соединителя | Обычный провод сохраняет ортогональную трассировку с изгибами. |

Поиск детерминирован и ограничен: для 2–4 перестраиваемых проводов перебираются
все порядки, для большего числа — приоритеты по сложности и циклические сдвиги.
Единичный маршрут ищется на сетке с ограничением 250 000 узлов. Это поиск лучшего
найденного варианта, а не доказательство глобального математического оптимума.
Проводники экрана рассчитываются после покрываемых им проводов.
Сохраняются допустимые ручные маршруты.

Если в направлении вывода экрана нет прямого участка цели либо общий узел
не может сдвинуться без нарушения других соединений, изменение экрана отклоняется
с предметной ошибкой; изгиб автоматически не создаётся. Ограничения топологии
и прямого отвода не заменяются фиктивной успешной трассой.
