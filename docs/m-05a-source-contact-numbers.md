# M-05A — исходные числовые номера контактов

26.09.2026. Первый срез продолжения по аудиту `plan-m-audit-2026-09-25.md`.
Исходная точка `8897383`; историческую нумерацию M4 не переименовываем.
Цель карточки: 10/20 в библиотеке остаются 10/20 в размещённом экземпляре,
таблице Э4 и подписях соединений после сохранения и переноса.

## Реализация

- Новое размещение получает номер из `snapshot.contacts.sourceNumber`,
  а не из индекса строки. `libraryBinding.contactNumbering = "source-v1"`
  отмечает этот контракт. Электрические ID и логические ID прежние.
- Клиент и сервер проверяют ASCII-число 1–300 (действующий диапазон),
  числовую уникальность, совпадение с закреплённым контактом по logical ID.
  `01`/`1`, `A1`, 0, 301, дробь или экспонента не заменяются молча порядковым номером.
  Неизвестная версия контракта отвергается. Сервер проверяет placement и design PUT,
  а также export/import через общий validator привязки.
- Старые документы без маркера сервер продолжает читать и переносить.
  Клиент сначала проверяет старый контракт, затем атомарно восстанавливает
  числовые номера из снимка и отмечает `source-v1`, включая уже совпадающие 1/2.
  Порядок контактов/строк, ID, связи, координаты и снимок не переписываются.
  Разный порядок snapshot/contacts сопоставляется по logical ID.
- Если старые номера нечисловые или неоднозначные, экземпляр остаётся читаемым
  с прежними номерами и диагностикой в свойствах/InfoHint. Новое размещение
  требует исправления исходных номеров. Нечисловая система обозначений вне M-05A.
- Предпросмотр редактируемой библиотеки допускает промежуточные значения,
  чтобы неверный номер можно было исправить. Такой preview не отправляется
  как новое размещение через `componentPlacementRequest`.

## Проверки

- Клиент: 1363 теста Vitest (137 файлов), TypeScript, production Vite build.
  Регрессии: 10/20, legacy 1/2 → 10/20, повторное чтение, подключённый провод,
  стабильные точки Э4/чертежа, подписи таблиц, неизвестный контракт,
  недопустимые/неоднозначные номера, переставленный snapshot.
- Сервер: 923 теста, 0 ошибок/пропусков, полный Release-прогон решения.
  38 focused проверок охватывают placement/PUT, неизменность revision/design/
  placement при отказе, copy/export/import schema 3/4/5, backup startup.
- Браузер: Edge через установленный Playwright, Browser plugin not available.
  Изолированный URL `http://127.0.0.1:5193/m05a-qa`, 1200×850 и 390×844.
  Настоящие материализатор v5, команды соединения, parser и E4ConnectorInspector:
  два экземпляра 10/20 → провод X1:10–X2:20 → кнопка сохранения/повторного чтения.
  Номера и endpoints сохраняются, таблицы непустые, overlay/ошибок страницы нет.
  В браузере проверялся JSON round-trip; серверная запись и перенос — API-тестами.

Команды: `node src/Techmap.Client/node_modules/vitest/vitest.mjs run --root
src/Techmap.Client`; `tsc --noEmit --project src/Techmap.Client/tsconfig.json`;
Vite build из каталога клиента; `dotnet test Techmap-Grapher.slnx
--configuration Release --no-restore -- --minimum-expected-tests 1`.
Установленные пакеты запускались напрямую, без переустановки зависимостей.

## Границы

Это закрытие числовой M-05A, не всего MVP и не всей M-04. Серверная целостность
остального электрического графа, защита от старых клиентов по всем новым полям,
и сохранность черновиков остаются отдельными карточками. SQLite schema и версия
portable-пакета не менялись; новый ZIP/EXE и семь portable-режимов не выпускались.
Пользовательские проекты не открывались и не изменялись.
