# М4-64–65: запуск с сохранёнными снимками компонентов

## Ошибка и причина

С1 и журнал startup-error-20260921-053255-8644.log: запуск останавливается в
SqliteStorageBackupService.ValidateProjectComponentSnapshots с сообщением
«The SQLite backup has an invalid project component ownership graph».

М4-64 воспроизвёл эту же цепочку исключений двумя обычными операциями:
- удалить жгут с библиотечными компонентами;
- скопировать проект, затем удалить все библиотечные компоненты из копии схемы.

Снимок принадлежит проекту и защищён от удаления до удаления самого проекта.
Размещения принадлежат жгуту и могут исчезнуть раньше. Проверка ошибочно требовала
хотя бы одно размещение у каждого снимка, хотя модель хранения допускает его отсутствие.

Исправлена только проверка существования размещений. Межпроектные связи, foreign_key_check,
integrity_check и проверки структуры снимков продолжают проверяться. Схема остаётся 20;
SQL-миграция, очистка и изменение пользовательской базы не нужны.

## Обновление и границы проверки

На другом компьютере закрыть старую программу, распаковать ZIP в новую папку и запустить
Techmap.Server.exe. При стандартном запуске используется существующее локальное хранилище.
Если ранее запускали с --data-root, сохранить тот же параметр. Не удалять папку данных.

База другого компьютера не предоставлена, поэтому точное состояние его записей не установлено.
Исправлены подтверждённые штатные сценарии с той же ошибкой. Реальная межпроектная
несогласованность по-прежнему блокирует запуск; если ошибка останется, нужен новый журнал
для следующей диагностики. Пользовательские проекты не открывались и не удалялись.
