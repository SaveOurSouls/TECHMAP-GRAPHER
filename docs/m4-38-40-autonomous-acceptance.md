# М4-38–М4-40 — автономная приёмка после восстановления

Основа: `1873153`, ветка `codex/restore-20260918-0235`. При старте рабочее дерево
чистое. Работа продолжена в актуальной корневой копии: прежняя
`.build/e4-library-fix` содержит исторический срез, а восстановленные М4-34–М4-37
находятся в корне. Пользовательские проекты не открывались и не изменялись.

## М4-38 — аудит

- Прочитаны AGENTS.md, план, состояние, протокол М4-37 и правила
  `techmap-harness-views`.
- Повторный API smoke версии М4-37: библиотечное размещение, закреплённая версия,
  таблицы, размеры и расчёт резки после перезапуска — успешно.
- Обнаружен дефект: CSS `resize: both` менял лишь DOM-размер окна таблицы.
  Ширина и высота отсутствовали в документе, поэтому не восстанавливались
  при повторном открытии редактора и не участвовали в Ctrl+Z.

## М4-39 — исправление

- Необязательные `width`/`height` в таблицах чертежа, в экранных пикселях.
  Размер шрифта и окна не зависит от масштаба чертежа; положение свободного
  окна по-прежнему задаётся в координатах чертежа.
- Угловой маркер с захватом указателя: промежуточный размер — локальный preview,
  отпускание — одна команда документа. Отмена жеста не меняет документ.
  Стрелки на маркере изменяют размер с шагом 10 px, Shift — 40 px.
- Для закрепления справа/снизу маркер находится у свободного угла и изменяет
  размер относительно закреплённого края. Объяснение находится в InfoHint.
- Клиент и сервер одинаково проверяют диапазоны: ширина 280–4000 px,
  высота 160–4000 px. Невалидная запись не изменяет ревизию.
  Старые документы без размеров используют прежние 760 × 380 px.
- Обычный клик по заголовку больше не создаёт пустую команду перемещения.

## М4-40 — проверки

- Клиент: 841/841 тестов, TypeScript и production build.
- Сервер: 753/753 тестов, Release publish.
- API итогового EXE: templateId/version/hash/article, рисунок с массивом на 12
  контактов, масштаб, общий графический контакт, физические маршруты, таблицы,
  размеры и резка. После перезапуска проверен весь документ, включая ширину,
  высоту и закрепление таблиц.
- Браузер: окно резки 640×360 → 580×410; один Ctrl+Z вернул 640×360.
  Клавиатурное изменение дало 650×370; закрепление снизу и размер восстановились
  после выхода и повторного открытия редактора. Спецификация перемещена
  за заголовок и растянута до 680×400; соединения — до 680×340, затем закреплены
  справа. Значения физических длин остались 100,125 + 200,125 = 300,25 мм.
- ZIP `artifacts/m4-40/TECHMAP-GRAPHER-win-x64.zip`, версия `0.40.1-m4-40`.
  SHA-256: `08C682036BD309EAEAE6211A488A21F0B77380311DDF474803C683D560C43655`.
  `verify-package` проверил 38 файлов по манифесту.

В зачёт вошли только успешные итоговые проверки. Первый запуск сервера в песочнице
остановился на чтении Windows ACL; проверка с необходимым доступом прошла.
Ранний клиентский прогон выявил синтаксическую ошибку промежуточной реализации,
исправленную до полного прогона. API-флаг `--check-drawing-targets` создаёт
иллюстрации без контактов и несовместим с новой проверкой полного рисунка;
отдельные `targets`/`array` также требуют базовый `--check-drawing-editor`.
Эти пробные конфигурации не засчитаны как пройденные; сценарий `targets`
в этой карточке не подтверждён. Итоговая команда:

```powershell
node scripts/test-library-placement.mjs artifacts/m4-40/TECHMAP-GRAPHER --independent-e4 --check-drawing-editor --check-drawing-array --check-drawing-placement --check-drawing-scale --check-common-drawing --check-drawing-workspace --check-topology --check-documents --check-cut-diagram --check-restart
```

## Границы

Пользовательская приёмка на реальном жгуте остаётся добровольной и не подменяется
тестовым проектом. Новые функциональные карточки сверх обнаруженного дефекта
не открывались. Коммит и push в этой задаче не выполнялись: переданные пользователем
правила требуют отдельного поручения координатора. Прежнее разрешение на публикацию
сохранено в истории, но для этой задачи применены более поздние ограничения.
