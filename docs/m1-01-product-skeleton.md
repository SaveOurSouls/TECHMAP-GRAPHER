# M1-01: product-каркас и переносимый web-ZIP

Статус: завершено 2026-09-12. Это первая карточка M1, а не готовая V1 и не
итоговое ТЗ или инструкция.

## Результат

Создан product solution модульного монолита: Domain, Contracts, Application,
пустая граница Infrastructure.Sqlite, ASP.NET Core Web, React/TypeScript Client
и два тестовых проекта. SQLite и предметная модель этой карточкой не вводились.

Закреплены .NET SDK 10.0.401 / Runtime 10.0.12, pnpm 11.19.0, React 19.3.0,
TypeScript 7.0.2, Vite 8.3.0 и точные транзитивные зависимости. NuGet и pnpm
lock-файлы входят в Git. Офлайн-генератор SPDX 2.3 учитывает 144 записи, а пакет
содержит проверенные уведомления сторонних компонентов и исходный notices-файл
.NET runtime.

Обычный браузерный клиент обращается к `/api/v1`; один bundle работает из `/`
и `/techmap/`. Хост слушает только loopback на случайном или заданном порту,
проверяет health и открывает системный браузер. Данные находятся вне программы;
в M1-01 сервер создаёт только совместимый маркер выбранного `dataRoot`.

Self-contained Windows x64 ZIP содержит один `Techmap.Server.exe`. При каждом
запуске до создания `dataRoot`, Kestrel и браузера сервер сверяет точный состав,
размеры и SHA-256 с `PACKAGE-MANIFEST.json`. Команда `--verify-package` выполняет
ту же проверку без запуска сервера.

## Проверки

Единый сценарий `scripts/test-m1-01.ps1` прошёл 2026-09-12:

- frontend strict typecheck, 14/14 Vitest и production build;
- locked NuGet restore для win-x64, build без предупреждений, 43/43 .NET tests;
- 20/20 регрессионных тестов M0 и три синтаксические проверки стендов;
- package manifest и 23 сценария его повреждения/некорректных путей;
- чистая распаковка в путь с кириллицей и пробелами;
- запуск с `DOTNET_MULTILEVEL_LOOKUP=0`, фиктивным `DOTNET_ROOT` и без Node;
- UI, runtime config, health, deep link и JSON 404 в `/` и `/techmap/`;
- bind `127.0.0.1`, случайный порт, отсутствие dev-каталогов, symbols/source maps
  и неожиданных внешних URL в web assets.

Архив имеет размер 42,58 МиБ, распакованный пакет — 99,25 МиБ при бюджетах
75/200 МиБ. В браузере визуально проверен экран проектов из фактического ZIP.

## Ограничения

SHA-256 обнаруживает случайное повреждение, но не подтверждает издателя; цифровая
подпись остаётся M9. Запуск на физически другом чистом Windows-компьютере также
остаётся M9. Сетевой аудит уязвимостей NuGet не входит в офлайн-сценарий и должен
работать отдельной проверкой при доступе к сети.

Single-instance, защищённая HTTP-сессия, полная проверка идентичности `dataRoot`,
UNC/junction/8.3 случаи и изменяющий API относятся к M1-02. Сохранение проектов,
SQLite, backup и миграции выполняются следующими карточками M1.
