# M-03: аварийный журнал жгута

Журнал хранится в `data-root/recovery/<project GUID>/<harness GUID>/<draft GUID>.json`.
Он не привязан к браузерному origin или порту. SQLite schema не меняется.
Перенос всего data-root переносит журнал; backup базы и экспорт проекта включают
сохранённые производственные документы, но **не аварийные копии**. Для отдельного
переноса копии интерфейс предоставляет JSON с обеими версиями.

Каждый сеанс пишет собственный GUID и возрастающую sequence. Запись сначала
сбрасывается на диск во временный файл и затем атомарно переименовывается.
Старые sequence отклоняются; повтор идентичного запроса идемпотентен. Удаление
требует совпадения sequence, поэтому запоздавшее подтверждение не удаляет новую
правку. Лимит — 1 МиБ локального содержимого и 32 копии на жгут. При достижении
лимита существующие копии остаются на месте; клиент сообщает об отказе записи.

Файл сохраняет локальный документ и серверный документ с ревизией при создании
этой копии. Автоматическое сохранение удаляет только журнал текущего сеанса.
Предыдущие и параллельные копии видны отдельно. Восстановление сначала создаёт
отдельный durable архив локальной и текущей серверной версии и только затем
применяет локальное содержимое через обычный механизм сохранения/проверки ревизии.
Если архивировать версии не удалось, восстановление не применяется. Удаление
старой копии — отдельная явная кнопка; обе версии можно скачать до удаления.

Browser localStorage остаётся синхронным резервом до ответа сервера. Отказ getter,
quota или запрет localStorage не блокирует редактирование и имеет видимую ошибку.
Отказ серверного журнала сообщает, что восстановление доступно только в прежнем
браузере/порту; отказ обоих хранилищ предлагает скачать текущую копию. При полном
сбое машины до ответа сервера и недоступности браузерного резерва сохранение не
гарантируется — интерфейс не выдаёт такое состояние за защищённое.

Проверки: серверные API/store тесты покрывают перезапуск одного data-root на
портах 18821 → 18822, сохранность обеих версий и неизменность live документа,
CSRF, повреждённый файл, ограничения, ошибку IO, монотонность и условное удаление.
Клиентские тесты проверяют сериализацию write/delete, новый GUID после save,
сохранение архива конфликта, продолжение после отказа и заблокированный getter.

Браузерная проверка: настоящий `HarnessDesignEditor`, синтетические API-ответы,
Edge/Playwright, `http://127.0.0.1:5193/recovery-qa`, 1440×1000. Проверены
восстановление конфликта с предварительной durable записью текущего dirty документа,
видимое сообщение при одновременном отказе localStorage getter и серверной записи,
кнопка скачивания, запоздавший save ACK после следующей правки (новый журнал не
удалён). Непустой редактор, без framework overlay и ошибок страницы.
Browser plugin отсутствовал; применён установленный Playwright/Edge. Скриншоты и
скрипт находятся в TEMP, в репозиторий не включены. Мобильный размер не проверен.
