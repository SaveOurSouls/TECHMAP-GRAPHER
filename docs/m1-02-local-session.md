# M1-02: владение `dataRoot` и локальная HTTP-сессия

Статус: завершено 2026-09-12. Карточка вводит защитный контур до появления
изменяющих предметных API; SQLite и сохранение проектов относятся к M1-03/M1-04.

## Владение каталогом данных

Сервер до инициализации данных открывает каталог без `FILE_SHARE_DELETE`, получает
его физическую идентичность (серийный номер тома и 128-битный File ID) и захватывает
именованный Windows mutex для этой идентичности. Mutex удерживается до остановки
процесса. Итоговый путь определяется через `GetFinalPathNameByHandleW`, поэтому
длинный путь, регистр, относительный путь, junction и доступный 8.3 alias приводят
к одному lease. UNC и сетевые диски запрещены; разные локальные roots работают
независимо. Пользовательские lock-файлы в `dataRoot` не участвуют в протоколе.

После аварийной остановки ОС освобождает mutex. При гонке с завершением прежнего
процесса новый запуск повторно открывает существующий каталог, снова проверяет
локальность и получает lease только при точном совпадении физической идентичности.
Подмена каталога по прежнему пути не считается продолжением прежнего root.

Живой владелец только после запуска Kestrel и успешной health-проверки публикует
запись обнаружения в закрытом `%LOCALAPPDATA%\TECHMAP-GRAPHER\sessions-v2`.
Имя записи вычисляется из физической идентичности `dataRoot`; каталог и файл сразу
создаются с отключённым наследованием ACL и доступом только текущему SID Windows.
Запись содержит физическую идентичность, URL, instance ID, PID и время старта;
session token, CSRF nonce и путь к данным в неё не записываются. Повторный запуск
проверяет ACL, PID/время, точный loopback URL и совпадение instance ID с health.
При успехе он открывает URL владельца и завершается; при недоказуемом владельце
выдаёт `instance_owner_unverifiable` и не становится вторым writer.

## HTTP-сессия

Сервер принимает запросы только через точный `http://127.0.0.1:<listener-port>`.
Проверяются локальный адрес соединения, Host и порт; `localhost`, IPv6 alias,
чужой/отсутствующий порт и чужое имя отклоняются. CORS не включён.

При выдаче SPA сервер устанавливает случайный 256-битный session token в cookie:
`HttpOnly`, `SameSite=Strict`, без Domain/Expires/Max-Age, с Path приложения.
Независимый 256-битный CSRF nonce клиент получает из `/api/v1/session` только после
проверки cookie и хранит в памяти. Оба значения живут до остановки процесса и
сравниваются fixed-time. Они не входят в URL, HTML, runtime config, файлы или логи.

Все POST/PUT/PATCH/DELETE под `/api` требуют одновременно точный Origin, session
cookie, `X-Techmap-CSRF` и `application/json`. Заголовки ответов запрещают referrer,
framing, формы на чужой origin и ненужные browser permissions. Health/runtime config
остаются безопасными bootstrap endpoint без пользовательских данных.

## Проверки

- frontend strict typecheck и 20/20 Vitest;
- 79/79 .NET tests без предупреждений;
- реальные Windows lease-тесты: case/relative, junction, 8.3, два roots, подмена
  каталога, враждебный старый lock-файл, повторное получение и освобождение после kill;
- текущий SID и ACL instance record, PID/start marker, несовпадающий instance ID;
- матрица Host/port, cookie, CSRF, Origin, JSON content type и отсутствие CORS;
- self-contained ZIP из пути с кириллицей/пробелами: дочерние процессы проверяют
  alias-пути, разные roots, одновременный burst, смену владельца после kill до
  публикации URL и повторный запуск; режимы `/` и `/techmap/` работают.

## Граница карточки

Lease действует между процессами одного Windows-компьютера. LAN-согласование и
многопользовательская аутентификация не входят в V1. Session cookie работает на
loopback HTTP; для будущего LAN обязательны HTTPS, Secure cookie и отдельная модель
идентификации. Цифровая подпись пакета и чистый внешний Windows-ПК остаются M9.
