# ADR-0025: общий транспорт JSON API

- Статус: реализовано для проверки владельцем.
- Источник: исходный запрос REQ-155; конкретная граница выделения — решение исполнителя по обнаруженному дублированию.
- Карточка: [120](../../tasks/120-system-assessment-and-api-refactor.md).
- Связанные решения: ADR-0003, ADR-0005, ADR-0021.

## Контекст

Четыре клиента API повторяли отправку запроса, настройки credentials/cache, проверку HTTP-статуса и чтение JSON. Их политика ошибок различается: проекты используют обычный Error для сетевого сбоя, документ/карта резки — свои классы; справочник сохраняет AbortError и оборачивает ошибки предметной валидации. Эти различия используются вызывающим кодом и должны сохраниться.

## Решение

`api-transport.ts` владеет только жизненным циклом JSON-запроса. Фабрика `createJsonRequest` получает runtime config, fetcher и обработчик HTTP-ошибок; необязательные политики формируют исключения сетевого сбоя и нечитаемого JSON. Успешный JSON передаётся типизированному парсеру вне transport catch. Путь собирается существующим `buildApiUrl`; RequestInit, включая signal и CSRF-заголовки, передаётся без изменения.

`project-api.ts`, `reference-catalog-api.ts`, `editor/design-api.ts`, `harness-cut-list-api.ts` сохраняют публичные интерфейсы, маршруты, сериализацию, response parsers, error parsers и revision/writer contracts. Справочник сохраняет прежнее оборачивание ошибок парсера. Транспорт не повторяет запросы: при потере ответа мутация уже могла выполниться на сервере.

Другие API пока сохраняют свои жизненные циклы (включая бинарные ответы и HTTP 204). Общий транспорт не приобретает флаги, нужные только одному такому клиенту. Расширять применение следует вместе с отдельными проверками его контракта.

## Последствия и проверка

Одна реализация транспортного механизма обслуживает четыре области системы, не связывая инфраструктуру с editor/manufacturing. Ошибки HTTP, JSON и предметной модели остаются разными фазами. Новые регрессии проходят через публичные API; прежние проверки подтверждают basePath, CSRF, конфликты, writer contract и отмену. Требуются полный Vitest и TypeScript/Vite. Формат документов, серверные endpoints и пользовательские сценарии не меняются.
