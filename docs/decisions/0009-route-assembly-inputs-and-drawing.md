# ADR-0009: входы и рисунок сборки маршрута

- **Статус:** принято для реализации 01.10.2026; ручная приёмка открыта
- **Источник:** поручение владельца от 01.10.2026, пункты 3–4
- **Требования:** REQ-054, REQ-055; инварианты REQ-008, REQ-010, REQ-034
- **Рабочие карточки:** [029](../../tasks/029-route-assembly-drawing.md), [030](../../tasks/030-route-assembly-inputs.md)

## Контекст

В текущем контракте сборка хранит `sourceObjects`, `dependsOn` и рисунок. Пустая
сборка моделью допускается, но кнопка интерфейса её блокирует. По массивам
невозможно устойчиво показать каждое отдельное добавление сырья или
полуфабриката как строку с собственной командой удаления. Рисунок исходного
жгута нельзя менять ради производственного представления этапа.

## Решение

У сборки появляется необязательный список `assemblyInputs`: каждая запись имеет
устойчивый ID и ссылку либо на объект сырья, либо на производящую строку
полуфабриката. Одно действие «Добавить» или drop создаёт одну запись. Состав
источников и `dependsOn` согласованы с этими записями; для старых сборок без
списка входы материализуются при первом редактировании. Удаление входа убирает
соответствующую ссылку и снимает готовность сборки и зависимых этапов.

Рисунок сборки редактируется как копия чертёжной геометрии с теми же ID
комплектующих. В строке хранится только геометрия выбранного фрагмента и
непрозрачность фона. Полный жгут допускается как контекст внутри редактора, но
после сохранения превью этапа показывает только выбранный фрагмент. Координаты
рисунка не меняют заданную длину, физический или электрический граф.

## Последствия и проверка

Парсер, команды изменения и `route-rebase` должны согласованно обрабатывать
новые входы и старые документы. Проверяются пустая сборка, два способа
добавления, удаление, DAG, повторное открытие, сохранение рисунка и неизменность
исходного чертежа. Схема UML строится по сохранённым ID зависимостей; отдельный
граф электрических связей не создаётся.
