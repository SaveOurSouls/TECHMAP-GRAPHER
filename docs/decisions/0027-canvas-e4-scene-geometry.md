# ADR-0027: геометрия сцены Э4 вне CanvasViewport

- Статус: реализовано для проверки владельцем.
- Источник: исходный запрос REQ-157, карточка [122](../../tasks/122-canvas-e4-scene-geometry.md). Выбор блока — техническое решение исполнителя.
- Связанные решения: ADR-0003, ADR-0026.

## Контекст

После выделения соединителей CanvasViewport содержит 3759 строк. Расчёт сегментов, overlays и hit-test Э4 не использует React, но находится рядом с рисованием и жестами. Эти расчёты используют общий порядок объектов, которым также пользуются Чертёж и остальной canvas. Обратный импорт этого порядка из CanvasViewport сделал бы новый модуль зависимым от UI.

## Решение

`editor/canvas-e4-scene.ts` владеет типами и чистыми вычислениями геометрии сцены Э4: сегментами/проекциями, пересечениями/мостами, разбором metadata, layout диффпар/экранов, их hit-test и видимостью. Определение позиции экрана по указателю экспортируется внутри этого модуля для существующих обработчиков CanvasViewport. Вычисления и правила fallback не меняются.

`editor/canvas-paint-order.ts` содержит прежний общий порядок объектов без изменения тела функции. CanvasViewport и геометрия используют одну реализацию; порядок физических точек, аннотаций и изображений соединителей не дублируется.

CanvasViewport сохраняет прежние публичные функции/типы через переэкспорт. Обработчики указателя, React-состояние, рисование, bounds и команды документа остаются в своих местах. Новые модули не импортируют CanvasViewport/React и не обращаются к глобальному DOM. Граница зависимости: CanvasViewport → E4 scene → paint order/types/model/geometry helpers.

## Последствия и проверка

CanvasViewport: **3759 → 3151 строк**, на 608 строк короче. Новый доменный модуль содержит 641 строку; общий порядок — 34. Это разделение ответственности без изменения пользовательских сценариев, форматов или производительности по обещанию.

Characterization-проверки создаются до переноса на `2d5c1be`, проходят после без обновления эталона геометрии. Прежние проверки жестов, экранов, диффпар и порядка слоёв используют публичный путь CanvasViewport. Дополнительно сравниваются перенесённые блоки и весь оставшийся код viewport: кроме import/export и EOL, реализации совпадают. Полный клиентский набор и TypeScript/Vite обязательны; сервер и поставка ZIP в этот перенос не входят.
