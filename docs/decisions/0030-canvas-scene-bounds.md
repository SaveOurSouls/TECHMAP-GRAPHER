# ADR-0030: границы сцены вне CanvasViewport

- Статус: реализовано для проверки владельцем.
- Источник: исходный запрос REQ-160, [карточка 125](../../tasks/125-canvas-scene-bounds.md). Выбор блока — техническое решение исполнителя.
- Связанные решения: ADR-0003, ADR-0026–0029.

## Контекст

После выделения hit-test CanvasViewport содержит 2679 строк. Расчёт границ сцены для вписывания в экран использует видимые объекты, контакты, библиотечные проекции, разделку, оболочки и overlays Э4, без React-состояния и CanvasRenderingContext2D. Подпись индекса соединителя используется и в расчёте границ, и при рисовании; толщина обводки разделки тоже должна оставаться общей.

## Решение

`editor/canvas-scene-bounds.ts` содержит прежние expandSceneBounds, drawingConnectorIndexLabel и getEditorSceneBounds. Модуль использует существующие geometry/layout/hit-test функции без обратной зависимости на CanvasViewport/React и глобальный DOM. Аккумулятор expandSceneBounds остаётся приватным.

Две публичные функции переэкспортируются из CanvasViewport; redrawCanvas импортирует ту же функцию подписи. Три константы оформления разделки вынесены в `canvas-wire-strip-style.ts`: прежние palette/outline используются viewport, stroke width — viewport и расчётом границ. Копии значения толщины и зависимость расчётов от renderer не вводятся.

## Последствия и проверка

CanvasViewport: **2679 → 2463 строки**, на 216 строк короче; bounds — 231 строка, shared style — 3. Перенесённый блок и стиль совпадают с исходником; весь оставшийся код от CanvasViewportProps совпадает после удаления двух блоков и нормализации export/EOL. Жесты, рисование, правила видимости и алгоритм fit не меняются.

Восемь characterization-проверок и шесть эталонов числовых границ сформированы до переноса через CanvasViewport; после переноса вызывается новый модуль. Отдельный тест закрепляет совместимость двух экспортов. Обязательны прежние 16 эталонов, профиль/полный Vitest и TypeScript/Vite. Ручная browser/portable-приёмка остаётся отдельной проверкой.
