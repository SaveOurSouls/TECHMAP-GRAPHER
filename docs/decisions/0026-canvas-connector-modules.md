# ADR-0026: геометрия и рисование соединителей вне CanvasViewport

- Статус: реализовано для проверки владельцем.
- Источник: исходный запрос REQ-156, карточка [121](../../tasks/121-canvas-connector-modules.md). Границы модулей — техническое решение исполнителя.
- Связанные решения: ADR-0003, ADR-0015, ADR-0021.

## Контекст

CanvasViewport содержит 4395 строк: React-взаимодействие, рисование сцены, hit-test и расчёт представлений. Контактный layout используется несколькими механизмами: рисованием, указателем, bounds и редактором таблицы. Перенос одного только рисования с повторным вычислением контактов мог бы рассогласовать эти механизмы.

## Решение

- `canvas-connector-layout.ts` владеет layout таблиц Э4, закреплёнными/legacy-контактами, glyph geometry, текстом ячеек и контактным hit-test. Функции чистые относительно сцены, не используют Canvas API, React или глобальный DOM.
- `canvas-connector-renderer.ts` использует этот layout для таблиц, контактных overrides и колец выделения. CanvasRenderingContext2D передаётся вызывающим кодом; состояние контекста сохраняется по прежнему протоколу.
- `canvas-scene-metadata.ts` содержит прежние `isRecord`/`parseJson`, общие для соединителей и overlays Э4. Правила fallback не меняются.
- CanvasViewport сохраняет React-жизненный цикл, жесты, порядок проходов, подписи/индексы, интеграцию drawing/template и вызовы renderer. Прежние публичные функции и типы переэкспортированы из того же пути для совместимости потребителей.

Направление зависимостей: CanvasViewport → renderer → layout → metadata/model/types; CanvasViewport также использует layout и metadata непосредственно. Обратных импортов новых модулей в CanvasViewport нет. Другие крупные блоки CanvasViewport в этой карточке не перепроектируются.

## Последствия и проверка

CanvasViewport уменьшен до 3759 строк, на 636 строк; layout — 370, renderer — 276, metadata — 12. Это уменьшение области ответственности, а не обещание ускорения UI.

Шесть контрольных render-traces получены до переноса на `6b1e130`, затем проверены без обновления snapshot. Они фиксируют хеш всей последовательности Canvas-команд и читаемые подписи/контактные точки. Прежние тесты взаимодействий продолжают использовать публичные экспорты CanvasViewport. Три перенесённых implementation-блока совпадают с исходником после нормализации import/export и окончаний строк; вычисления и порядок команд не менялись. Полный клиентский набор и TypeScript/Vite обязательны; новые серверные или package-проверки для изменения только клиентских границ не требуются.
