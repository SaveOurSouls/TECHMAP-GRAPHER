# Архитектурные решения

[ADR-0025 — общий транспорт JSON API](0025-json-api-transport.md): REQ-155, карточка 120; общий жизненный цикл запроса при сохранении предметной политики ошибок.

[ADR-0024 — схемы заготовки провода](0024-wire-preparation-schemes.md): REQ-152, карточка 117; независимые цепочки и снимки операций БД.ОП.

[ADR-0023 — исключение старых страниц маршрута](0023-retire-legacy-route-pages.md): REQ-153, карточка 118; V3 использует общие производственные модули, UML импортирует V3.

[ADR-0022 — явное изменение состава проводов П](0022-explicit-pipe-wire-membership.md) фиксирует ручное добавление, устойчивое исключение и перенос физического маршрута карточки108.

[ADR-0021 — runtime-контракт многопроводных оконцовок](0021-termination-runtime-contract.md) фиксирует реализацию карточки 104 и конкретизирует проектный ADR-0020.

ADR с номерами `0001`–`0007` восстановлены из кода и истории. [ADR-0008](0008-route-source-synchronization.md) фиксирует действующую в коде политику обновления источника маршрута по последующему поручению владельца. Статус действующего решения описывает реализацию, а не завершённую ручную приёмку.

Для нового решения создать следующий `NNNN-краткое-имя.md`:

```markdown
# ADR-NNNN: название

- Статус: предложено | принято | заменено ADR-NNNN
- Источник: исходный запрос | найдено в коде | предположение
- Связанные требования: REQ-###

## Контекст

Проблема, ограничения и альтернативы.

## Решение

Что выбрано и кем подтверждено.

## Последствия

Что упрощается, что усложняется, как проверяется.
```

Если решение меняется, старый ADR помечается как заменённый со ссылкой на новый. Исторический текст не переписывается так, будто прежнего выбора не было.
