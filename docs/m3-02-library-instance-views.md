# M3-02 — закреплённые библиотечные виды в жгуте

Дата начала: 2026-09-14.

## Цель

Размещённый библиотечный компонент должен показывать в Э4 и чертеже графику той
версии шаблона, которая была закреплена в проекте при размещении. Новая версия
глобальной библиотеки не должна менять уже сохранённый жгут.

## Часть 1 — контракт чтения

Реализовано чтение активного графа библиотечных компонентов выбранного жгута:

- `GET /api/v1/projects/{projectId}/harnesses/{harnessId}/component-placements`
  возвращает размещения и только используемые ими project-owned снимки;
- каждый снимок содержит точные номер и SHA-256 исходной версии, полный JSON
  представлений, связи артикулов и метаданные PNG;
- одинаковый снимок возвращается один раз, даже если его используют несколько
  размещений;
- содержимое PNG читается через адрес, ограниченный проектом, жгутом, снимком и
  asset; чужой жгут не может получить изображение;
- клиент проверяет идентичность проекта/жгута, связи placement→snapshot,
  уникальность ID, формат содержимого и тип изображения до использования ответа.

Интеграционный тест создаёт версию шаблона с PNG, размещает её в одном жгуте,
публикует более новую глобальную версию и подтверждает, что API продолжает
возвращать закреплённую старую версию. Другой жгут получает пустой граф и `404`
на изображение.

## Следующая часть

Подключить контракт к редактору и отрисовать сохранённые узлы, слои, PNG и точки
контактов отдельно для видов Э4 и чертежа. Текущая табличная форма остаётся
резервным отображением для универсального компонента или шаблона без пригодной
геометрии. Дополнительные монтажные виды сохраняются в снимке; отдельное рабочее
поле для них не входит в первую визуальную часть.

Критерий приёмки: различимая графика Э4 и чертежа одного шаблона появляется в
соответствующих представлениях жгута, провод приходит в связанную библиотечную
точку, результат переживает перезапуск, копирование и export/import, а публикация
новой версии шаблона не меняет экземпляр.
