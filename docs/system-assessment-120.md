# Оценка системы и выполненных работ — 16.10.2026

## Выполнение плана рефакторинга

Пять крупных модулей и загрузка рабочих областей из этой оценки обработаны по REQ-161 / [карточке 126](../tasks/126-finish-editor-refactor.md); технические gates подтверждены [итоговым аудитом](editor-refactor-126-completion-audit.md). Числа и рекомендации ниже относятся к исходному срезу оценки и сохраняются как история. Продуктовая приёмка, решения о хранении и нативные длинные пути — отдельные работы, не закрытые структурным переносом кода.

## Вывод и основание

Проверенный продуктовый срез имеет развитую функциональность, автоматические регрессии и воспроизводимую упаковку. Главный технический долг сосредоточен в крупных клиентских модулях и повторяющейся инфраструктуре. Готовность к ручной приёмке нельзя выводить только из количества тестов: исходный пользовательский жгут и совместные сценарии последней интеграции остаются открытыми.

Основание оценки: чистый исходный HEAD `d4671ac` ветки `codex/integration-m5-22`, документация и статический разбор действующего кода, затем проверки карточки 120. Это инженерная оценка реализации и сопровождаемости; замеры нового пользовательского проекта и полная ручная приёмка в неё не входят. Сведения исторических рабочих веток не суммируются как независимые готовые функции.

## Выполненный рефакторинг

Добавлен `src/Techmap.Client/src/api-transport.ts`. Клиенты проектов, справочников, документа жгута и карты резки используют общий механизм отправки и чтения JSON. Сохранены URL и basePath, credentials/cache, CSRF, тела мутаций, expectedRevision, writerContractVersion, AbortSignal и предметные парсеры. Обработчики HTTP-конфликтов остались в API. Сетевой сбой, нечитаемый JSON и ошибка структуры документа не смешиваются; автоматических повторов нет. Решение закреплено в [ADR-0025](decisions/0025-json-api-transport.md).

14 новых регрессий проверяют совместимость через публичные API, в том числе запрет повторной отправки мутации при неизвестном результате и прежний receiver внедряемого fetcher. Ранее существовавшие тесты проверяют отмену запросов, текущую ревизию конфликта, basePath и writer contract. Изменения экранов, электрической модели и производственных длин не вносились.

- .NET Release build PASS, 0 warnings/errors: `dotnet build Techmap-Grapher.slnx --configuration Release --no-restore -m:1 -nr:false -p:UseSharedCompilation=false`.
- Полный серверный набор с архитектурными и доменными тестами PASS: **1142/1142**, без пропусков, 9 мин 21 с. Команда: `dotnet test Techmap-Grapher.slnx --configuration Release --no-build --no-restore --filter 'FullyQualifiedName!~ReferenceCatalogSearchPerformanceTests' -- --minimum-expected-tests 1`. Запуск вне песочницы, `TEMP`/`TMP` = `C:\Temp\techmap-120`.
- Отдельный performance gate PASS: **1/1**, 11 с; та же среда, команда `dotnet test tests/Techmap.Web.Tests/Techmap.Web.Tests.csproj --configuration Release --no-build --no-restore --filter 'FullyQualifiedName~ReferenceCatalogSearchPerformanceTests' -- --minimum-expected-tests 1`. Во время него другие проверки карточки не выполнялись.
- Первый клиентский запуск завершился ошибками ENOENT временного SSR-cache. Повтор с `TEMP`/`TMP` в `tmp/assessment-120/temp`, `pnpm --filter @techmap/client exec vitest run --maxWorkers=1` прошёл. Первоначальная команда с разделителем `--` перед именами файлов не ограничила набор; профильный baseline выполнен через `exec vitest run`.
- В песочнице `dotnet test` не запустил тесты из-за `UnauthorizedAccessException` IPC named pipes. Прямой запуск xUnit executable обошёл IPC, однако интеграционные проверки в длинном temp-каталоге рабочей копии дали Win32 «путь не найден» при `StorageGenerationLayout.MoveNewDurably`; такая ошибка наблюдалась и вне песочницы. Короткий temp-каталог разрешил полный штатный прогон. Это ограничение условий тестирования: длинные пути требуют отдельного воспроизведения и регрессии, поддержка всех путей этим прогоном не доказана. Серверный код в карточке 120 не изменён.
- После последней правки вызова fetcher параллельный повтор Vitest с тяжёлым .NET-набором дал два таймаута геометрических тестов и был остановлен. Окончательный последовательный прогон 209/2271 прошёл; thresholds тестов не менялись.
- Новый ZIP, ручной browser/portable и исходный пользовательский жгут в карточке 120 не проверялись. Owner acceptance открыта.
