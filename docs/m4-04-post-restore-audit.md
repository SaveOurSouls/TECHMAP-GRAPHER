## План текущей карточки M4-04

1. Воспроизвести принятие некорректного профиля регрессионным API-тестом.
2. Проверять оба конца, identity снимка, 1–64 слоя, индексы, положительные D/L,
   точность 0,001 мм и строгое возрастание. Сохранить пропуски индексов и
   совместимость документов без профиля. Не переписывать закреплённые нормы.
3. Использовать ту же проверку при импорте и экспорте; отказ должен происходить
   до публикации некорректного проекта. Проверить неизменность документа/ревизии.
4. Проверить переносимость корректных профилей, собрать `0.18.0-m4-04` и ZIP
   без пользовательских данных, записать фактические результаты.

SQLite остаётся schema 20, документ — schemaVersion 1. Новых полей и миграций
нет. Интерфейс сохраняет компактную компоновку и InfoHint.

## Проверки и ограничения

Статус: M4-04 завершена, версия `0.18.0-m4-04`.

Регрессия до исправления: 15/15 случаев дали ошибочное HTTP 200 вместо 400.
После исправления: 15/15 прошли, прежние документ и ревизия сохранены при отказе.
Отдельно прошли восемь проверок валидатора и тест импорта некорректного профиля
из архива с правильными SHA-256. Полная сборка: 717/717 клиентских тестов,
TypeScript и production build; 689/689 .NET-тестов, без пропусков.
В них входят экспорт с повреждённым профилем (архив не создаётся), переносимость
корректных профилей двух концов при copy/export/import и restart.

Проверка настоящего API итогового EXE с `--check-strip-profiles`: сохранён
валидный профиль с пропусками индексов, ошибка длины второго конца отклонена
HTTP 400 с полем `content.wires[0].stripProfiles.to.layers[1].stripLengthMm`;
прежняя ревизия и оба профиля сохранены. Повторно прошли размещение v5 новой
версии библиотеки и удаление только созданного одноразового проекта.
Все семь portable-режимов пройдены. `git diff --check` и синтаксис smoke-скрипта
проверены. UI в этой карточке не изменялся; его браузерная проверка — в M4-03-r6.
