# М4-46 — предложение: генератор рисунков серии

Статус: аудит и проектное предложение. Реализация не включена в эту карточку.
Основание: пользователь попросил предложить механизм «уникальный объект 1 —
период × N — уникальный объект 2», индивидуальные дополнения и просмотр вариантов.

## С1 и модель поведения

На С1 красным отмечена повторяемая ячейка, синим — торцевые части корпуса.
Рекомендуется хранить один исходный рисунок серии и параметры вариантов,
а итоговую геометрию вычислять для выбранного существующего артикула.
Один повтор — ячейка рисунка; целиком собранный вариант — рисунок артикула.
Несколько артикулов с одинаковым числом контактов могут использовать одну основу.

Объектам исходного рисунка назначаются роли:

| Роль | Поведение |
| --- | --- |
| Начало | Одна группа, закреплённая в системе координат исходного рисунка |
| Период | Одна группа фигур и контактных мест, повторяемая с заданным шагом |
| Конец | Одна группа, смещаемая при изменении количества периодов |
| Статичные объекты | Общая графика с одинаковыми координатами во всех вариантах; порядок слоёв сохраняется |
| Дополнения артикула | Отдельные объекты, принадлежащие только выбранному артикулу |

Для непрерывных верхней/нижней границ корпуса полезен дополнительный режим
«между началом и концом»: удлиняется линия или выбранный размер, а не весь объект.
Он нужен для рамок, где растяжение всей фигуры исказило бы толщину или скругления.

## Геометрия и контакты

Ориентация задаётся отдельно от нумерации: горизонтально или вертикально.
Автор задаёт опорную точку начала, начало периода и шаг. Позиции торцов рисуются
для базового количества периодов N₀. Для однорядного массива:

`позиция конца(N) = позиция конца(N₀) + (N − N₀) × шаг × направление`.

Начало и статичная графика не перемещаются. При N=1 конец существует один раз.
Для нескольких рядов смещение вычисляется по геометрическому числу колонок
вдоль оси роста, независимо от порядка обхода контактов. Последний номер змейки
может находиться у начала корпуса и не определяет положение торца.

Период может содержать одно или несколько контактных мест — например, целую
колонку двухрядного соединителя. Пусть K — количество строк контактов артикула,
F — число явно заданных неповторяемых контактов, q — число контактов периода.
Тогда N=(K−F)/q. Нецелый результат требует явной настройки неполного периода:
по умолчанию показывается диагностика, а лишние контакты не создаются молча.
Графику неполного корпуса необходимо определить отдельно.

Схема нумерации сопоставляет контактные места существующим строкам таблицы:
1–4 ряда, вдоль/поперёк, с начала ряда/змейка, исходный угол и направление.
Настройки можно менять в любое время. Геометрия ячеек при этом не меняется.
Номер берётся из колонки №, а электрическая связь — из устойчивого ID строки.
Подписи с произвольными номерами также поддерживаются. Изменение нумерации
переставляет места подключения, но не переименовывает и не пересоздаёт контакты
и провода. До сохранения показывается новый результат сопоставления.

## Редактор

В компактной верхней ленте — раздел «Генератор»: режим «Исходник / Артикул»,
кнопки назначения ролей выделению, ориентация, шаг и отдельная группа нумерации.
Длинных раскрывающихся блоков над полотном нет; пояснения — в InfoHint.

В режиме «Исходник» доступны все роли. Ползунок перебирает существующие артикулы
серии, рядом видны артикул, количество контактов и N. Стрелки дают точный переход.
Переключение варианта меняет только предпросмотр, не создаёт версии или Undo.
Редактирование периода, торцов и общей графики применяется ко всем вариантам.
Произвольное N для проверки геометрии можно задать отдельно без создания артикула.

В режиме «Артикул» отображается вычисленная основа и только его дополнения.
Основа доступна для выбора и просмотра, но недоступна для перемещения, удаления,
разгруппировки и изменения через общие свойства. Команда «Редактировать исходник»
переводит к соответствующей роли. Выделение из основы и дополнений не допускает
частичного незаметного удаления. Дополнения можно двигать, копировать и удалять;
по умолчанию их координаты локальные фиксированные, опционально — относительно
начала, конца или конкретного контактного места. При исчезновении такого места
после изменения N выводится диагностика, дополнение не удаляется.

Кнопка «Применить к серии» назначает генератор выбранным существующим артикулам.
«Сохранить и выйти» сохраняет исходник и дополнения. Изменение сохраняется одной
операцией Undo, а защиту основы проверяют команды, не только кнопки интерфейса.
Существующие рисунки других разделов сохраняют свои назначения Э4/Чертёж/Маршрут.
Размещённые компоненты сохраняют версионированный снимок; обновление библиотеки
не должно незаметно менять уже выполненные схемы.

## Аудит текущего кода и реализация

- `drawing-array-commands.ts`: количество уже определяется по артикулу;
  исходная группа хранится один раз. Ролей торцов и индивидуального слоя нет.
- `array-layout.ts`: геометрия и порядок нумерации сейчас связаны обходом;
  для нового генератора их необходимо разделить.
- `drawing-array-contacts.ts`: есть связь повторов со строками таблицы;
  её нужно сохранить, расширив явным сопоставлением контактных мест.
- `drawing-bindings.ts`: рисунок артикула — набор ссылок на общие объекты;
  это ещё не изолированные дополнения и не защищённая вычисляемая основа.
- `template-model-v2.ts` и сервер используют строгую проверку формата.
  Новые поля требуют согласованного изменения валидаторов, сохранения,
  импорта/экспорта и формирования снимков. Одного изменения клиента недостаточно.
- Preview, размещение в редакторе и экспорт должны использовать один вычислитель
  геометрии и контактных мест. ID экземпляров графики строятся из ID генератора,
  роли, ячейки и исходного объекта; контактные ID остаются ID таблицы.

Предлагаемый порядок последующих карточек:

1. М4-47: контракт генератора, клиент/сервер, вычислитель, совместимость старых
   массивов; горизонтальные/вертикальные варианты и независимая нумерация.
2. М4-48: режимы исходника/артикула, роли выделения, ползунок вариантов,
   индивидуальные дополнения, защита основы во всех командах и Undo.
3. М4-49: сквозная приёмка всех разделов, сохранение/повторное открытие,
   обновление версий, API, браузер и пакет без пользовательских данных.

Приёмка: варианты 2/10 контактов; N=1; вертикальный вариант; 2–4 ряда и змейка
без смещения торца; несовместимое число контактов; общий статичный логотип;
индивидуальный объект только у одного артикула; Delete/разгруппировка основы
запрещены; изменение исходника сохраняет дополнения; preview/размещение совпадают;
старый массив открывается без потери данных. Сохранение проверяет контактные ID
и полное соответствие таблице. Проверки выполняются на синтетических данных.

В М4-46 исходники приложения не изменены. Пробные изменения отменены только
в восьми файлах, чистых перед началом карточки. Изменения М4-40/41 сохранены.
