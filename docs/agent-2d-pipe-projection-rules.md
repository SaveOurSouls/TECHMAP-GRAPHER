# Правила агента: 2D-изображение пайпа и общей оболочки в чертеже

В редакторе переключатель «Объёмный режим пайпа» сохраняет `PhysicalSegment.mode`
(`flat` или `round`). Он меняет укладку и видимую проекцию проводов, а не
прозрачность или освещение оболочки. `round` использует детерминированную
касательную упаковку окружностей и first-hit видимые полосы; ширина П берётся
из описывающего диаметра пучка. Полный путь каждого `wireId` остаётся в сцене
для выбора и выделения. Выбранный провод целиком рисуется поверх П и ОП до
снятия выбора. Глобальный «Объёмный свет» управляет только светотенью.

Актуальные визуальные референсы: [только итерация v5](../design/references/harness-cross-sections/README.md). Ранние итерации удалены; не восстанавливать их из истории Git как образец для реализации.

Документ задаёт вычислимое правило для чертёжного изображения физического пайпа
и его общей защитной оболочки (ОП, `PhysicalCovering`). Изображение является
проекцией модели и кэшем отображения. Оно не является источником электрических
связей, маршрутов, длин или производственных параметров.

## 1. Входные данные

Агент получает одну закреплённую ревизию `HarnessDesignDocument` и формирует
объект проекции с такими полями:

```json
{
  "sourceId": "covering-or-pipe-id",
  "revision": "document-revision-or-hash",
  "view": {
    "direction": {"x": 1, "y": 0},
    "scalePxPerMm": 1,
    "widthPx": 1600,
    "heightPx": 1050
  },
  "wires": [],
  "shellLayers": [],
  "output": {"format": "png", "colorSpace": "sRGB"}
}
```

Обязательные данные провода: устойчивый `wireId` или `segmentId`, наружный
диаметр из закреплённого материала, цвет, принадлежность пайпу и порядок
участка маршрута. Диаметр берётся из `materialBinding.outerDiameterMm`, затем
из диаметра провода/контакта в библиотеке. Значение из пикселей, название
провода или номер строки таблицы диаметром не является.

Для общей ОП используются её устойчивый `id`, `spans`, `bundle.members`,
`bundle.mode`, вложенные оболочки, `bodyOffset` и стиль материала. Участки
`spans` сначала разрешаются через якоря маршрута, затем преобразуются в
интервалы изображения. Если маршрут не задан, агент сообщает «Маршрут не
задан» и не рисует подтверждённую физическую трассу по догадке.

Электрические ID, физические сегменты, вложенные оболочки и продолжения пайпа
разворачиваются рекурсивно, но каждый листовой сегмент попадает в сечение один
раз. Дубликаты, циклы вложенности и неизвестные участники — ошибка входа.

## 2. Единицы и направление вида

Все вычисления выполняются в миллиметрах чертежа. Перевод в пиксели выполняется
только на последнем шаге:

```text
pixel = originPx + scalePxPerMm · pointMm
```

Направление стрелки вида задаёт нормированный вектор `d = (dx, dy)` от ближней
стороны к дальней. Экранная ось, перпендикулярная лучам, равна
`n = (-dy, dx)`. Разворот стрелки меняет видимую сторону и поэтому должен менять
результат first-hit проекции.

Для центра `pᵢ` окружности используются локальные координаты
`uᵢ = dot(pᵢ, d)` и `vᵢ = dot(pᵢ, n)`. В них `u` — глубина луча, а `v` — его
координата на экране.

Пиксельные координаты, размеры картинок и сглаживание никогда не записываются
обратно в маршрут, длину, `spans`, `bodyOffset` или электрическую модель.

## 3. Поперечная укладка окружностей

Для каждого листового провода строится окружность
`Cᵢ = (uᵢ, vᵢ, rᵢ)`, где `rᵢ = outerDiameterMmᵢ / 2`.

В режиме `round` агент должен выбирать конфигурацию лексикографически:

1. максимальное число пар касающихся окружностей;
2. минимальный радиус взвешенной описывающей окружности `R`, содержащей каждую
   окружность целиком;
3. минимальная сумма зазоров и стабильный порядок ID как последний tie-breaker.

Допустимая конфигурация обязана выполнять для всех пар:

```text
distance(Cᵢ, Cⱼ) >= rᵢ + rⱼ - ε
```

Касание считается подтверждённым, если
`abs(distance(Cᵢ, Cⱼ) - rᵢ - rⱼ) <= ε`. Перекрытие окружностей запрещено.
`ε` задаётся в единицах модели и должен быть существенно меньше минимального
диаметра; его нельзя подбирать по размеру PNG.

Рекомендуемый детерминированный поиск для небольших сечений:

1. зафиксировать первую окружность в `(0, 0)`, вторую — касательно по оси `u`;
2. перебрать порядок проводов, зеркальное отражение и повороты результата;
3. для каждой следующей окружности построить кандидатов, касательных к каждой
   паре уже размещённых окружностей, через пересечение двух окружностей;
4. удалить кандидатов с пересечением уже размещённых окружностей;
5. для каждого полного кандидата пересчитать контакты и `R`, затем выбрать его
   по критериям выше;
6. центрировать только готовую конфигурацию относительно её описывающей
   окружности.

Если `bundle.mode === "flat"`, сохраняется авторский порядок пайпов вдоль
базовой линии. Соседние элементы касаются по линии, а глубина равна диаметру
самого широкого элемента. В `round` нельзя заменять окружности прямоугольными
полосами.

Окружность ОП вычисляется после укладки проводов. Для вложенной ОП сначала
вычисляется дочернее сечение, затем оно становится одним диском родительской
укладки. Ширина ОП может увеличивать внешний диаметр, но не меняет диаметры
внутренних проводов.

## 4. First-hit ортографическая проекция

Боковой вид строится лучами, а не перспективным рендером и не изометрией.
Для каждой строки/сэмпла экрана с координатой `v` проводится луч

```text
P(t) = v · n + t · d
```

Для окружности с центром `(uᵢ, vᵢ)` вычисляется `Δv = v - vᵢ`. Если
`abs(Δv) > rᵢ`, луч окружность не пересекает. Иначе ближнее пересечение:

```text
tᵢ = uᵢ - sqrt(rᵢ² - Δv²)
```

(при соглашении, что `d` направлен от наблюдателя в глубину). Для данного
сэмпла выбирается провод с минимальным `tᵢ`. В пиксель записывается только его
цвет — это первый цветной пиксель луча. Все более дальние провода для этого
сэмпла игнорируются. Если пересечений нет, пиксель остаётся пустым до нанесения
ОП.

Для продольного изображения маршрут разбивается на сохранённые прямые сегменты.
В каждой станции сегмента используется локальная ось маршрута и одна и та же
касательная укладка. Переходы между станциями интерполируются по центрам
проводов и оболочки; сплайны и перспективное сжатие запрещены. На перегибах
используются существующие точки маршрута, а не ближайшая геометрическая линия.

Сглаживание допускается только как supersampling: сначала вычисляется first-hit
на увеличенной сетке, затем выполняется downsample. Оно не должно смешивать
цвета двух проводов до выбора первого пересечения.

## 5. Нанесение ОП и порядок слоёв

ОП не участвует в выборе first-hit проводника. Она рисуется после wire layer
отдельным RGBA-overlay:

1. фон и служебная рамка;
2. first-hit слой проводов без чёрных контуров внутренних проводов;
3. внутренняя ОП;
4. внешняя ОП/термоусадка;
5. контур, выноски, размеры и подписи.

Для прямого участка ОП — полупрозрачный прямоугольный слой по границам
покрываемого интервала. Для ломаного маршрута строятся прямоугольные полосы по
каждому сегменту с согласованным стыком на перегибе. Нельзя рисовать одну рамку
вокруг всей группы, если `spans` покрывают только часть маршрута.

Параметры альфа-канала хранятся в стиле материала. Если стиль не задал альфу,
используется явное значение по умолчанию, достаточное для чтения проводов
под оболочкой (например, `0.35–0.60`). Нельзя рисовать RGBA-заливку прямо в
итоговый RGB-буфер и надеяться на последующее смешивание: сначала выполнить
`alphaComposite(base, overlay)`, затем сохранить PNG. При поддержке прозрачного
фона допускается экспорт RGBA; при вставке на белый лист выполняется явное
смешивание с цветом листа.

## 6. Связь с чертежом

Результат хранит `sourceId`, IDs проводов/сегментов/ОП, направление вида,
масштаб, границы изображения и хеш входной ревизии. Размещение картинки в
чертёже хранит якорь и размер, но не переписывает геометрию источника.

Кэш недействителен после изменения состава пайпа, диаметра, маршрута, `spans`,
`bodyOffset`, направления вида, масштаба или стиля ОП. Перестроение выполняется
из модели; пиксели старого изображения не используются как вход для следующего
расчёта.

Общая визуальная точка выхода пайпа не создаёт электрический узел. Настоящая
связь определяется только Э4. Выбор провода подсвечивает его полный физический
путь по ID, даже если часть этого пути скрыта first-hit проекцией.

## 7. Проверки перед выдачей PNG

Агент обязан остановить выдачу и вернуть диагностическое сообщение, если
нарушено хотя бы одно условие:

- отсутствует диаметр, цвет, устойчивый ID или маршрут, необходимый для данного
  режима;
- окружности пересекаются или минимальный зазор меньше `-ε`;
- конфигурация не содержит максимального найденного числа контактов;
- размер описывающей окружности не минимален среди кандидатов с тем же числом
  контактов;
- в тестовом луче виден дальний провод после первого пересечения;
- ОП закрывает провод непрозрачным слоем, хотя слой должен быть прозрачным;
- изображение изменяет электрические связи, длины, `spans` или точки маршрута;
- PNG сохранён без явной альфа-композиции либо имеет неверный размер/цветовой
  режим.

Минимальный набор автоматических тестов:

1. 2, 3, 4 и 5 окружностей с разными диаметрами: нулевой минимум зазора и
   воспроизводимое число контактов;
2. два пересекающихся по глубине провода: в каждом луче остаётся цвет только
   ближайшего;
3. разворот `direction`: видимый порядок проводов меняется предсказуемо;
4. нейлонка и термоусадка: цвета проводов читаются под RGBA-слоем;
5. частичный `span`: ОП присутствует только на заданном интервале;
6. вложенный пайп и продолжение сегмента: листовые IDs не дублируются;
7. повторная генерация той же ревизии даёт побитно стабильный PNG или стабильный
   хеш после нормализации метаданных.

Проверочный отчёт должен содержать `sourceId`, ревизию, направление, масштаб,
число проводов, число контактов, минимальный зазор, границы ОП, размер PNG и
список предупреждений. Предупреждение не должно маскировать отсутствие
подтверждённой геометрии.
