# Таблицы справочников по референсу С2

Запрос от 25.09.2026. Product Design: image-to-code, существующий компонент.

С1: поля ввода в шапке и каждой ячейке, технические идентификаторы,
ссылка на файл и настройки синхронизации мешали читать справочник.
С2: образец компактной таблицы с единой сеткой и светлой шапкой.

Реализация:
- Строки 36 px, текст 11 px, вертикальные и горизонтальные границы,
  чередование фона, закреплённые заголовки и номера строк, прокрутка внутри таблицы.
- Подписи и порядок стандартных справочников взяты из XlsxKnownProfiles.cs
  и docs/source-schema.md. Ключевые бизнес-поля остаются под исходными названиями
  (AWG, Номер, Инв. номер, Кабель). Тип записи, составной ключ, JSON слоёв,
  адрес файла и настройки синхронизации скрыты.
- D1–D3/L1–L3 редактируются в отдельных ячейках с обратным сохранением массива
  layers. Неизменённые типы значений, служебные поля и адреса исходных строк сохраняются.
- Добавление строк и столбцов вынесено над таблицей. Пустой добавленный столбец
  сохраняется вместе с порядком колонок. Редактирование доступно с клавиатуры.
- Импорт всех колонок проводов сохраняет порядок листа в скрытом поле
  _techmapColumnOrder. У старых снимков проводов известны только первые пять
  колонок; для полного исходного порядка остальных требуется повторный импорт.
  Стандартным шести справочникам повторный импорт для заголовков не нужен.

Проверки: TypeScript; полный Vitest (1285 тестов на общей рабочей копии,
включая параллельную задачу); 7 тестов редактируемой таблицы; production build;
901 .NET тест; браузерный стенд реального компонента (редактирование,
сохранение, добавление строки/столбца, удаление строки, Tab, узкая ширина,
пустая таблица). Консоль браузера без ошибок.

Браузерный стенд использует демонстрационные данные и локальный обработчик
сохранения. Рабочие базы пользователя не изменялись. Сборка выдаёт прежние
предупреждения о размере JS и импортах HEIC. Диагностические снимки и стенд
находятся в игнорируемых tmp; в коммит не включаются.
