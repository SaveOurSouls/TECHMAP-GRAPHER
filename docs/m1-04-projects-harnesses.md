# M1-04: проекты и независимые жгуты

Статус: завершено 2026-09-12, предметная модель уточнена после проверки владельцем.
Карточка добавляет первый предметный срез системы: проекты, их независимые жгуты и
рабочий web-интерфейс. Редакторы объектов жгута, Э4 и графики относятся к следующим
этапам; самостоятельные рабочие области документов уже закреплены за каждым жгутом.

## Модель и хранение

Project и Harness имеют созданные сервером стабильные UUID. Проект служит контейнером
для жгутов и хранит обозначение, глобальный положительный инкремент, название и ручной
статус `draft`, `active` или `completed`. Инкремент выдаётся единым долговечным
счётчиком внутри `BEGIN IMMEDIATE`; конкурентные создания не получают одинаковое
значение.

Жгут всегда принадлежит одному проекту и имеет собственное положительное количество.
Его обозначение не является идентификатором и может совпадать с обозначением жгута
другого проекта. Явный `sort_order` сохраняет порядок независимо от UUID и названия;
удаление не меняет ID и позиции оставшихся жгутов, поэтому в порядке допустимы
промежутки. Новый жгут добавляется после максимальной существующей позиции.
Количество ограничено диапазоном точных целых браузера, чтобы значение не менялось при
передаче между JSON, JavaScript и SQLite.

Каждый жгут получает три самостоятельных документа со стабильными UUID: `e4`,
`drawing` и `route`. До реализации предметных редакторов они имеют честный статус
`empty`. Количество и комплект документов сохраняются после перезапуска и входят в
копию, экспорт и импорт проекта.

В проекте разрешено не более 100 жгутов. Проверка количества и вставка выполняются
одной транзакцией; SQLite-триггер служит дополнительной защитой всех путей записи.
Попытка добавить 101-й жгут возвращает `409 harness_limit_reached` и не меняет проект.

Копирование создаёт новый Project UUID, новый инкремент, новые Harness UUID и новые
UUID документов. Оно сохраняет обозначение, название, состав, порядок и индивидуальные
количества жгутов. Статус копии — `active`. Производственный выпуск, брак, фактическое
время и результаты контроля не будут переноситься при появлении соответствующих таблиц
M8. Источник не изменяется.

## API и интерфейс

Версионированный API предоставляет список и чтение проектов, создание, изменение,
копирование, добавление и удаление жгута. Чтение требует локальную session cookie;
запись также требует точные Origin, CSRF и JSON из M1-02. Ошибки имеют стабильный код,
поле и сообщение. Пути к БД, connection string и данные сессии не возвращаются.

Web-интерфейс показывает список и поиск проектов, форму создания, карточку выбранного
проекта, статус, копирование, счётчик и быстрый поиск по жгутам. Количество задаётся при
создании жгута и меняется только у выбранного жгута. Выбор жгута открывает его параметры
и вкладки «Схема Э4», «Чертёж», «Маршрут». Закрытие карточки снимает выбор только в
браузере. Глобальный «открытый проект» в БД не хранится, чтобы несколько вкладок и
будущие пользователи LAN не перезаписывали выбор друг друга.

## Схема и совместимость

Storage schema 2 добавляет `project_counter`, `projects`, `harnesses`, индекс порядка и
триггер лимита. Уточняющая schema 6 добавляет `harnesses.quantity` и
`harness_documents`. При миграции прежнее проектное количество переносится в каждый
существующий жгут. Значение выше максимального точного целого JavaScript безопасно
ограничивается до `9 007 199 254 740 991` при переносе и выдаче через API; исходное
проектное поле остаётся только как служебное legacy-поле для совместимости. Исходная
миграция M1-03 остаётся неизменной с прежним ID и SHA-256.
При открытии точной schema 1 приложение проверяет историю и атомарно добавляет schema 2;
неизвестная или повреждённая цепочка по-прежнему приводит к явной ошибке.

Это узкая добавочная миграция технической schema 1 без предметных данных. Общий
candidate/backup механизм для следующих миграций остаётся M1-10–M1-12.

## Проверки и граница

Автоматические проверки охватывают сохранение UUID и порядка после перезапуска,
100/101 и конкурентное добавление, конкурентный инкремент, копию без изменения
источника, удаление, валидацию и защищённый API с URL-префиксом. Клиент проверяет DTO,
base path, CSRF и сообщения об ошибках.

Финальный прогон: frontend 24/24, .NET 132/132, регрессия M0 20/20, Release build
без предупреждений. Self-contained Windows x64 ZIP 45,51 МиБ (106,8 МиБ распаковано)
прошёл семь portable-режимов. Внутри распакованного пакета созданы проект и два жгута;
перезапуск сохранил UUID, инкремент и порядок. Независимый review не оставил P1/P2
после канонизации переводов строк при расчёте SHA-256 миграций.

В M1-04 не входят предметное содержимое Э4, чертежа и маршрута, объекты и холсты.
Перестановка жгутов также пока не является отдельной командой: хранится и
воспроизводится порядок добавления.
