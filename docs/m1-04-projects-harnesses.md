# M1-04: проекты и независимые жгуты

Статус: завершено 2026-09-12. Карточка добавляет первый предметный срез системы:
проекты, их независимые жгуты и рабочий web-интерфейс. Объекты жгута, Э4 и графика
относятся к следующим этапам.

## Модель и хранение

Project и Harness имеют созданные сервером стабильные UUID. Проект хранит отдельные
обозначение, глобальный положительный инкремент, название, количество партии и ручной
статус `draft`, `active` или `completed`. Инкремент выдаётся единым долговечным
счётчиком внутри `BEGIN IMMEDIATE`; конкурентные создания не получают одинаковое
значение.

Жгут всегда принадлежит одному проекту. Его обозначение не является идентификатором
и может совпадать с обозначением жгута другого проекта. Явный `sort_order` сохраняет
порядок независимо от UUID и названия; удаление не меняет ID и позиции оставшихся
жгутов, поэтому в порядке допустимы промежутки. Новый жгут добавляется после
максимальной существующей позиции.

В проекте разрешено не более 100 жгутов. Проверка количества и вставка выполняются
одной транзакцией; SQLite-триггер служит дополнительной защитой всех путей записи.
Попытка добавить 101-й жгут возвращает `409 harness_limit_reached` и не меняет проект.

Копирование создаёт новый Project UUID, новый инкремент и новые Harness UUID, сохраняет
обозначение, название, количество партии, состав и порядок жгутов. Статус копии —
`active`. Производственный выпуск, брак, фактическое время и результаты контроля не
будут переноситься при появлении соответствующих таблиц M8. Источник не изменяется.

## API и интерфейс

Версионированный API предоставляет список и чтение проектов, создание, изменение,
копирование, добавление и удаление жгута. Чтение требует локальную session cookie;
запись также требует точные Origin, CSRF и JSON из M1-02. Ошибки имеют стабильный код,
поле и сообщение. Пути к БД, connection string и данные сессии не возвращаются.

Web-интерфейс показывает список и поиск проектов, форму создания, карточку выбранного
проекта, статус и партию, копирование, счётчик и быстрый поиск по жгутам. Закрытие
карточки снимает выбор только в браузере. Глобальный «открытый проект» в БД не хранится,
чтобы несколько вкладок и будущие пользователи LAN не перезаписывали выбор друг друга.

## Схема и совместимость

Storage schema 2 добавляет `project_counter`, `projects`, `harnesses`, индекс порядка и
триггер лимита. Исходная миграция M1-03 остаётся неизменной с прежним ID и SHA-256.
При открытии точной schema 1 приложение проверяет историю и атомарно добавляет schema 2;
неизвестная или повреждённая цепочка по-прежнему приводит к явной ошибке.

Это узкая добавочная миграция технической schema 1 без предметных данных. Общий
candidate/backup механизм для следующих миграций остаётся M1-10–M1-12.

## Проверки и граница

Автоматические проверки охватывают сохранение UUID и порядка после перезапуска,
100/101 и конкурентное добавление, конкурентный инкремент, копию без изменения
источника, удаление, валидацию и защищённый API с URL-префиксом. Клиент проверяет DTO,
base path, CSRF и сообщения об ошибках.

Финальный прогон: frontend 24/24, .NET 132/132, регрессия M0 20/20, Release build
без предупреждений. Self-contained Windows x64 ZIP 45,51 МиБ (106,8 МиБ распаковано)
прошёл семь portable-режимов. Внутри распакованного пакета созданы проект и два жгута;
перезапуск сохранил UUID, инкремент и порядок. Независимый review не оставил P1/P2
после канонизации переводов строк при расчёте SHA-256 миграций.

В M1-04 не входят вложения, версии команд, idempotency, autosave, Ctrl+Z, импорт,
экспорт, производственный факт, Э4, объекты и холсты. Перестановка жгутов также пока
не является отдельной командой: хранится и воспроизводится порядок добавления.
