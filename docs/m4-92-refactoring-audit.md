# М4-92 — завершение рефакторинга физической топологии

Рефакторинг по исходным пяти пунктам завершён. Область: маршрутизация пайпов,
авторская/вычисляемая геометрия, выходы, граница сцены и Canvas, временные
совместимые обходы. Это не утверждение о рефакторинге всех остальных подсистем.

## Проверка требований

| Требование | Реализация и подтверждение |
| --- | --- |
| Отдельный модуль маршрутизации пайпа | `pipe-routing.ts` — чистый вычислитель без UI, хранения и React; `physical-geometry.ts` связывает его с моделью. `pipe-routing.test.ts`, `physical-topology.test.ts` проверяют направления, 45°, ручные точки и перенос. |
| Авторские точки отдельно от вычисленной геометрии на уровне модели | `PhysicalPath` в `physical-topology-model.ts`: routed / polyline, только авторские points. Вычисленные углы возвращаются отдельно; ручки сцены берутся из авторских точек. `physical-path-migration.test.ts`, `physical-scene.test.ts`, `pipe-editing.test.ts` проверяют отсутствие мутации, миграцию, разбиение, удаление точек, повторное открытие и Undo. |
| Направления и выходы отдельно | `physical-ports.ts` разрешает локальные/мировые координаты, направление узла и контакта с поворотом рисунка. Клиентская и серверная валидация проверяют направления и принадлежность контактов. `HarnessPhysicalPathTests`, тесты physical-topology покрывают эти границы. |
| Canvas — отрисовка и взаимодействие | `physicalTopologyScene` строит точки/ручки/направления/ID жил вне Canvas. Canvas не импортирует вычислитель маршрутов, сохранённую топологию или её кодек. Удалён запасной построитель Э4 и неиспользуемый дубль изменения сегмента; рисование и hit-test используют одни переданные points. Перемещение выполняется командами модели. Проверены editor-workspace, commands и браузер. Геометрия попадания мышью, декоративных линий и рисования остаётся обязанностью Canvas. |
| Удалить временные обходы | В runtime-модели нет `routing=fixed` и верхнеуровневого bends. Кодек читает старые документы один раз; новый формат сохраняет явную polyline даже без внутренних точек. Старые значения встречаются только на границе чтения/серверной совместимости и в проверках миграции. Реэкспорты функций не содержат альтернативных алгоритмов. |

Дополнительно разделены валидация, операции редактирования, поиск путей проводов
по графу и отображение жил (М4-90). Сохраняются электрические ID, ручные маршруты,
направления, покрытия, привязки размеров и производственные длины.

- API на итоговом пакете: синтетический проект, ветвления, отдельные выходы,
  обратные маршруты, ID, спецификация, редактирование пайпа, общие размеры;
  запись старого формата → чтение/миграция → запись нового → перезапуск → чтение.
  Все сравнения прошли (`artifacts/m4-92-api.log`).

- ZIP проверен по манифесту и списку файлов: базы, логи и пользовательские данные
  отсутствуют. Внутри только приложение, зависимости, лицензии и штатные примеры.
