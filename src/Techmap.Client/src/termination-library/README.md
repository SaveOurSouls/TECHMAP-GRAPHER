# Runtime-библиотека оконцовок · REQ-135

Библиотека переносит принятые проектные SVG карточки 099 в приложение. В ней 25
форм, включая восемь вариантов Разделки; стандартный и широкий раструбы НШВИ
имеют по шесть цветовых исполнений. Это шаблоны формы, а не вымышленные артикулы:
производитель, артикул, размеры, ток и физическая совместимость изначально неизвестны.
Обозначение DIN/SC в названии формы не подтверждает нормативное соответствие артикула.

## Экспорты для редактора

- `TerminationLibraryPicker({onSelect, onClose?, selectedId?, view?, storage?, error?})`
  выбирает запись, создаёт и редактирует пользовательский артикул. `onSelect`
  получает валидированную `TerminationLibraryRecord`, включая выбранный цвет.
  `view` — `e4` или `drawing`, по умолчанию `drawing`.
- `TerminationRecordEditor({record, onSave, onCancel, disabled?})` — отдельная форма.
  При переключении редактируемой записи используйте `key={record.id}`.
- `getTerminationSymbol(selection, view)` / `getTerminationSymbolById(id, view, colorId?)`
  возвращают URL, viewBox, pivot и якоря; неизвестный ID возвращает `null`.
  Selection принимает `assetId` или `symbolId`, `colorId` или `color` и
  `preparationMode`. `TerminationSymbol` показывает тот же SVG как React `img`.
- `createTerminationPlacement(record, {id, designation, position})` синхронно
  возвращает `{connector, artifact?}` для атомарной команды
  `add-termination-component`. Компонент имеет один обычный контакт, гильза — два.
- `terminationArtifactFromRecord(record, id)` создаёт экземпляр материального
  наконечника/гильзы для назначения существующему контакту. Для Разделки бросает
  ошибку: она не является самостоятельным материальным артикулом.

Фабрики сохраняют полный нормализованный payload записи и его настоящий SHA-256
в `catalogBinding`. Редактирование локальной записи впоследствии не меняет уже
размещённый снимок. Пустой артикул остаётся пустым; название шаблона используется
лишь для допустимой подписи соединителя.

## Данные и совместимость

Размерные поля зависят от семейства; неизвестные числа представлены `null`,
поправки резки/зачистки могут быть отрицательными. Сечения задаются в мм².
Условия описывают проводники **на одном входе**: число, диапазон сечения каждого
проводника, явные комбинации, материалы жил и источник подтверждения. Схема
отклоняет противоречивые комбинации и диапазоны. Цвет, ширина раструба и число
электрических точек не доказывают физическую совместимость.

`evaluateTerminationCompatibility` возвращает `compatible`, `incompatible` или
`unknown`. Без подтверждения и источника результат неизвестен. Текущая модель
документа проверяет только явные комбинации сечений; диапазоны и остальные поля
сохраняются в pinned payload. При ограничении материала жил адаптер оставляет
`capacity.confirmed=false`: достоверного состава жил в текущем WireMaterialBinding
нет. Марка провода не подменяет материал. Операции, группировка проводов и нормы
времени принадлежат модели редактора и не выводятся из графики библиотеки.

## Хранение и ассеты

Пользовательские записи сохраняются в localStorage под
`techmap.termination-library.v1`; можно передать `StorageLike` для другого
локального хранилища. Схема и ID проверяются при чтении и записи. Ошибка чтения или
переполнение показываются пользователю; повреждённые данные не перезаписываются.
Это локальный справочник, отдельной сетевой синхронизации нет. Снимок выбранной
записи переносится вместе с документом.

`sync-assets.py` воспроизводимо переносит 62 используемых SVG из
`design/termination-099` в `termination-library/symbol-assets`: Чертёж сохраняет принятые
цвета, Э4 использует монохромную краску при той же геометрии. Манифест сохраняет
provenance исходников и их SHA-256. Порт наконечника/Разделки — `(32,50)`, у гильзы
второй — `(188,50)`; отверстия и сочленения дополнительных портов не создают.
SVG импортируются через Vite `?url&no-inline` и получают хешированные имена внутри
`dist/assets`. Production-сервер раздаёт именно `/assets`; прежние запросы к
`/termination-symbols/*.svg` не обслуживались этим middleware и возвращали 404.
URL учитывают Vite base и серверный path base. Не переносите SVG обратно в public
с прямыми URL без проверки реальной раздачи production-сервера.

## Проверки

Из `src/Techmap.Client`: `npm run typecheck` и
`npx vitest run src/termination-library --no-file-parallelism --pool=threads`.
Тесты покрывают схему, локальное хранение, независимость совместимости от цвета,
актуальные SVG/якоря, SHA-256, все 25 размещений с JSON round-trip и SSR формы.
В Windows sandbox стандартный fork pool Vitest/Vite может потерять временный
SSR-модуль до выполнения тестов (`Temp/ssr ENOENT`); thread pool с сохранённой
изоляцией файлов и отдельный запуск SSR-файла проходят. Интеграция в сцену и браузерная
проверка редактора выполняются владельцем UI.

Для регрессии доставки после production build и запуска настоящего .NET host:
`node src/termination-library/verify-production-assets.mjs dist http://127.0.0.1:PORT/`.
Повторите с настроенным path base, например `/techmap/`. Проверка требует все 62
хешированных файла, MIME `image/svg+xml` и совпадение полученных байтов с dist;
одного HTTP 200 недостаточно. Компактное окно использует внешние классы
`he-termination-backdrop` / `he-termination-modal`; интеграционную ошибку передают
через `error`, чтобы она оставалась внутри текущего окна.

## Компактные границы рисунков

`artwork-bounds.ts` хранит видимые границы 62 SVG (штрихи и якоря включены), измеренные генератором `generate-artwork-bounds.mjs`. Границы служат выделению и размещению индекса; исходный SVG, его масштаб и электрические якоря не меняются. Размеры выражены в условных координатах viewBox, а не в миллиметрах артикула.

После изменения принятых SVG запустите `node generate-artwork-bounds.mjs <путь-к-модулю-sharp>` и проверки `termination-scene.test.ts`. SHA-256 каждого исходника защищает таблицу от незаметного устаревания. Sharp нужен только для обновления таблицы, не для приложения или обычного запуска тестов.
